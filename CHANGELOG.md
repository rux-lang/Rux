# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Each release groups its entries under **Added**, **Changed**, **Removed**, and **Fixed**, subdivided by area (Language, Packages, CLI / Package Manager, Tooling, Platform, Runtime / Linker) when a section is long enough to need it.

## [Unreleased]

Introduces compile-time programming (`when`, `intrinsic`, `#`-prefixed compiler context), native AArch64 host support on every platform, an explicit `let`/`var` mutability model, and a consolidated, hermetic test tree.

### Added

#### Language

- **`when` — conditional compilation** — `when cond { ... } else when cond { ... } else { ... }` evaluates its condition while compiling and keeps only the taken branch; untaken branches are never resolved or type-checked, so they may reference symbols that do not exist on the current build. `if` remains the run-time conditional, and a chain keeps the keyword it opened with — `else if` inside a `when` chain is an error. Conditions are built from `const` declarations, enums, literals, imported compile-time intrinsics, and the usual operators. `when` works between declarations and inside a function body, where it introduces no scope of its own. A condition that is not a compile-time constant, or not a `bool`, is an error.
- **`when` match over a compile-time value** — `when <subject> { pattern => body, ... else => body }` keeps only the matching arm: `when #target.os { .Windows => PrintLine("win"), .Linux => PrintLine("linux"), else => #Error("Unsupported OS") }`. Arm patterns are enum variants or literals, an arm may list several comma-separated patterns, and `else` is the default. An arm body is an expression, a `{ ... }` block, or — between declarations — a declaration or an `#Error`/`#Warn` directive. If no arm matches and there is no `else`, the build is an error.
- **`intrinsic`** — marks a declaration the compiler supplies rather than Rux source: `intrinsic #target: Target;` and `intrinsic func Assert(condition: bool, message: char8[]);`. A `#`-prefixed name marks a compile-time value or function (`#target`, `#Error`); ordinary runtime intrinsics (`Assert`, `Panic`) and methods keep their plain names. An intrinsic value has no initializer and an intrinsic function has no body. Replaces the `#Intrinsic("Name")` attribute and the `$` sigil.
- **Compile-time build context** — importing the Core package exposes ordinary values for the target (`#target.os`, `.arch`, `.abi`, `.endian`, `.pointerBits`, `.dataModel`, `.objectFormat`, `.triple`, `.HasFeature(...)`), build (`#build.profile`, `.mode`, `.optimization`, `.debugAssertions`, `.debugInfo`, `.isTest`, `.outputKind`, `.timestamp`, `.date`, `.time`), compiler (`#compiler.version`, `.HasFeature(...)`), and source location (`#source.line`, `.column`, `.file`, `.fileName`, `.filePath`, `.function`, `.module`). `#config.Get("name")` and `#config.Has("name")` read user-defined build values.
- **`#target.os` and the `OperatingSystem` enum** — `#target.os` is a compile-time value of the built-in `OperatingSystem` enum, so a build selects platform code with `when #target.os == .Windows { ... }`. Each variant is a system rather than a family — `Windows`, `Linux`, `macOS`, `FreeBSD`, `OpenBSD`, `NetBSD`, `DragonFlyBSD`, `Illumos`, `Solaris`, `Android`, `IOS`, `AIX`, `Haiku`, `Fuchsia`, `QNX`, `Redox` — so the BSDs are told apart. A variant may be written as `Enum::Variant` or as the `.Variant` shorthand when the other side fixes the enum. A variant the enum does not have is an error; one no build target can currently produce is a warning. A condition may only name an intrinsic or built-in enum the file has brought into scope.
- **`#Error` and `#Warn` compile-time directives** — `#Error("message")` and `#Warn("message")` emit a diagnostic at the call site and produce no runtime code, so a build can reject an unsupported configuration: `when #target.os == .Windows { #Error("Windows is not supported yet"); }`. They run after `when` folds, so a directive in an untaken branch never fires. The message must be a string literal.
- **Intrinsic assertions** — importing `Assert` or `DebugAssert` from the Core package enables compiler-backed assertions that report the message, function, file, line, and column before trapping. Release builds remove `DebugAssert` checks without evaluating their arguments.
- **Intrinsic panic and no-return functions** — importing `Panic` from the Core package enables compiler-backed panic reporting and termination. `#NoReturn()` marks user or extern functions that never return and makes calls terminate their control-flow path without adding a new type or keyword.
- **`byte` primitive alias** — `byte` is the raw-storage spelling of `uint8`, with identical representation, ABI, constants, conversions, and overload identity. Memory operations use it for byte-addressable views while numeric code can retain the explicit `uint8` spelling.
- **Primitive associated constants** — Boolean, character, integer, and floating-point types expose their storage width through `Bits` and `Bytes`. Integers and characters also expose `Min` and `Max`; floating-point types expose `Lowest`, `Max`, `MinPositive`, `Epsilon`, `Infinity`, and `NaN`. The `bool`, `char`, and `float` aliases forward to their canonical widths, while `int` and `uint` follow the compilation target.
- **Future primitive type reservation** — documented primitive names whose representations are not implemented yet, such as `int128`, `float16`, and `char128`, are reserved and produce a compiler-version diagnostic instead of being reported as unknown types.
- **Code units and scalar values** — each character width states what it carries. `char8` and `char16` hold one unit of an encoding, so every value that fits is valid and a `char16` may hold a UTF-16 surrogate, which is exactly a code unit. `char32` and every wider character hold a Unicode scalar value, so they stop at U+10FFFF and reject the surrogate range whatever room the width has beyond it. Every width is checked by the same rule, where previously only `char8`, `char16`, and `char32` were checked at all and a surrogate was rejected even for the width whose job is to carry one.
- **Character widening follows the encoding** — a character widens implicitly only to a wider character carrying the same thing, so `char32` widens to `char64` and the two code-unit widths widen to nothing. `char8` no longer widens implicitly to `char16` or `char32`, and `char16` no longer widens to `char32`: a UTF-8 byte above `0x7F` is not the UTF-16 word of the same number, and a UTF-16 word may be half of a pair rather than a character. An explicit cast between any two character widths is unchanged.
- **`char64`** — the fourth character width is implemented, carrying a Unicode scalar value in eight bytes and exposing `Min`, `Max`, `Bits`, and `Bytes`.
- **`bool64`** — the fourth boolean width is implemented, joining `bool8`, `bool16`, and `bool32`. It stores one of two values in eight bytes, exposes `Bits` and `Bytes`, converts to and from the other widths without changing what it means, and is passed at its own width rather than promoted when handed to a C variadic function, since C has no type to promote it to.
- **Normalized boolean casts** — a cast into a boolean asks whether the whole source value is non-zero, so `256 as bool` is `true`. The value stored is always zero or one at every boolean width, whether the cast is folded while compiling or performed at run time. Previously the source was truncated to the boolean's storage width first, which made `256 as bool` yield `false` while `2 as bool` yielded `true`.
- **Wide integer literal suffixes** — `i128`, `i256`, `i512`, `u128`, `u256`, and `u512` join the numeric literal suffixes, and a literal of any width is decoded exactly rather than through a machine word, so a 512-bit value is read without loss. The suffix list a diagnostic offers is generated from the same table the lexer validates against.
- **Suffixed literals are range-checked** — `256u8` and `-129i8` now report `integer literal is out of range for type 'uint8'` where they were silently accepted. A suffixed literal names its own type, so nothing else was checking it; an unsuffixed literal was, and still is, checked against whatever it is assigned to. The most negative value of a signed width stays in range, since it is written as a magnitude one past the largest positive one.
- **Passing an enum with a payload by value** — an enum whose variants carry data is sized by its tag plus its widest payload rather than by its tag alone, so passing one to a function carries the whole value. Previously only the tag was passed and the callee read whatever sat past it, which corrupted the payload and could crash. An enum that is nothing but a discriminant is unchanged and still travels in a register as the integer it is stored as.
- **Logical right shift** — signed integers support `>>>` and `>>>=` to shift in zero bits while preserving the left operand's type and fixed width; `>>` remains arithmetic for signed integers and logical for unsigned integers.
- **Whole-module import** — `import Pkg;` binds a dependency's eponymous `module Pkg` as a namespace, so its members are used through `Pkg::Name` (e.g. `import Windows;` then `Windows::HeapAlloc(...)`). A package that exposes no same-named module still requires naming an item, and `import Pkg::Module` / `import Pkg::{ A, B }` / `import Pkg::*` are unchanged.
- **Inline assembly functions** — `asm func Name(...) -> T { ... }` bodies are written directly in x86-64 (Intel syntax) and assembled to machine code, bypassing the normal HIR/LIR pipeline. Supports the common instruction subset (ALU ops, `mov`/`lea`, `movzx`/`movsx`, the multiply/divide group, shifts, `push`/`pop`, `call`/`jmp`, the full `jcc`/`setcc` family, `ret`/`leave`/`nop`/`syscall`), register/immediate/memory operands, local labels, and calls to other functions. A body is read and assembled for the architecture the build targets: an AArch64 build accepts AArch64 register names and operand syntax (`#imm`, `[Xn, #off]`, `[Xn, Xm, LSL #3]`, `[Xn], #off`, `[Xn, #off]!`, `X1, LSL #3`, `B.EQ`) and encodes the body itself, and a body whose instructions belong to the other architecture — an `imul` in an AArch64 build, an `ldr` in an x86-64 one — is an error naming the mnemonic that gives it away. One function reaches both machines by writing a body per architecture under `when #target.arch`.
- **`Self` in an interface** — an interface method may write `Self` where it means the type implementing the interface, so a binary operation can say that its other operand, or its result, is the same type as its receiver: `interface Equatable { func Equals(other: *Self) -> bool; }`. `Self` resolves to the type argument at each instantiation of a generic bounded by the interface, with no dynamic dispatch. There are no generic interfaces, so this is the only way to express such an operation. A method naming `Self` cannot be called through an interface value, where the implementing type is unknown and two values of one interface may hold different types; the call is rejected and points at using a generic bound instead.
- **`#Allow("naming.const")`** — preserves a constant's published spelling on a single declaration, the way `#Allow("naming.type")` already does for a type. A binding's constant is a foreign macro's own name — `SEEK_SET`, `O_RDONLY`, `FILE_ATTRIBUTE_NORMAL` — which no reader porting code would recognize renamed, and which the naming rules already carve out for raw declarations. Rejected on anything that is not a constant.
- **Targeted lint allowances** — `#Allow("naming.type")` preserves intentional foreign type, field, and variant spellings on a single type declaration without disabling naming checks elsewhere.
- **Deterministic destruction** — a type implementing `Core::Drop` has its body run when a value of it is destroyed, and so do the fields, tuple elements, array elements, and enum payloads it contains, in reverse construction order. Destruction happens at ordinary scope exit, at a return, at `break` and `continue`, on the value an assignment overwrites, and where `?` leaves the function early. Each destroyed type gets one synthesized glue function taking the value's address, and each destruction point calls it guarded by the binding's drop flag — so a value moved away is destroyed once, by its new owner, even when the move happened on only one branch. Panic and process termination still do not unwind. Not yet emitted: the parts already built when constructing an aggregate fails, and the payload of a non-generic enum, which is stored packed beside its tag with no room for a droppable value.

#### Packages

- **`Core` integer arithmetic at every width** — `AddChecked`, `SubChecked`, `MulChecked`, `AddWrapping`, `SubWrapping`, `MulWrapping`, `AddSaturating`, `SubSaturating`, `MulSaturating`, plus `MaximumOf` and `MinimumOf`, generic over the integer type. The operation comes first in each name because `CheckedAdd` and its two companions already name the compiler's `uint64` intrinsics, which are emitted inline and are what allocation-size arithmetic is written with. One implementation serves all sixteen integer types, signed and unsigned: a type's zero, all-ones pattern, signedness, and limits are all derived from one operand and `sizeof`, so nothing is written out per width. The checked operations never trap, including the one signed pair — the most negative value by `-1` — whose quotient has no answer and which is reported before the check would attempt the division.
- **`Core` bit and byte-order operations at every width** — `CountOnes`, `CountZeros`, `LeadingZeros`, `TrailingZeros`, `LeadingOnes`, `TrailingOnes`, `RotateLeft`, `RotateRight`, `ReverseBits`, `ReverseBytes`, `BitAt`, `BitWidthOf`, `IsPowerOfTwo`, and `ShiftRightLogical`, plus `ToLittleEndian`, `FromLittleEndian`, `ToBigEndian`, `FromBigEndian`, `StoreLittleEndian`, `StoreBigEndian`, `LoadLittleEndian`, `LoadBigEndian`, and `TargetIsLittleEndian`. One implementation serves all sixteen integer types, deriving the width from `sizeof` and the type's zero and one from a single operand. Signedness is the thing these have to get right: `>>` is arithmetic on a signed type, so every operation that reads a value's bits as bits goes through `ShiftRightLogical`, which brings zeros in at either signedness. The store and load pair moves a value through raw bytes at any alignment, which is what a file or wire format needs, and `TargetIsLittleEndian` establishes this target's byte order from its own storage rather than from a list of known targets.
- **`Rux/Memory` alignment, unaligned access, byte order and zeroization** — `IsAligned`, `IsPointerAligned`, `AlignUp`, `AlignUpChecked` and `AlignDown`; `LoadUnaligned` and `StoreUnaligned`, which go through bytes and so are correct at any address on any machine; `LoadLittleEndian`, `LoadBigEndian`, `StoreLittleEndian` and `StoreBigEndian`, which are what a file or wire format actually needs; `ReverseBlock`; and `ZeroizeBlock`, which carries `Core::Zeroize`'s compiler guarantee with this module's empty-case contract. `AlignUpChecked` exists because `AlignUp` wraps where rounding would pass the end of the range, and a wrapped size is an allocation far smaller than the caller asked for.
- **`Rux/Memory` page allocation, release and protection** — `PageAllocate`, `PageRelease`, `PageProtect`, `PageSize` and `PageAlign`, with one `PageError` across four systems that report failure three different ways: an errno, a `GetLastError` code, and a sentinel address. Protection is a flag set this package defines rather than any one platform's. Windows separates reserving address space from committing storage to it and these calls always do both, which is what every other system does and what an allocator expects. A zero length or a null address is reported rather than quietly accepted. `Rux/Windows` gains its `GetLastError` code constants and `GetSystemInfo`, and `Rux/macOS` gains `getpagesize`, which is what makes the page size asked rather than assumed on the two systems that will answer.
- **`Rux/Allocator`** — a new package holding the allocation contract and the allocators that meet it. `Layout` is a validated size-and-alignment pair: `Layout::New` is the only way to build one and refuses an alignment that is not a power of two, or a size whose rounding would pass the end of the address space, so nothing downstream checks again. `AllocError` names why an allocation did not happen, since null cannot tell a request that was too large from one the system refused. The `Allocator` interface is the bound a generic requires, with four promises every implementation keeps: the address satisfies the layout, the contents are undefined, a release must match its allocation, and a failure leaves everything alone. `SystemAllocator` asks the page layer rather than a C heap, which is what lets it honour an alignment stricter than a word; a header before each block records what to give back, and a release that does not match is reported rather than corrupting the next allocation. A zero-sized layout gives a shared non-null aligned address, so an empty collection is not a special shape.
- **`Rux/Collections` `Vector<T>` owns what it holds** — the vector takes an allocator at construction and keeps it, implements `Drop`, and is move-only; `Free` is gone. Destruction destroys every element it holds and then releases the block, and the spare capacity past the length holds nothing and is not touched. `Truncate` and `Clear` destroy exactly the elements they drop, `ShrinkToFit` on an empty vector hands the storage back entirely, and a reservation that cannot be represented is refused as arithmetic with the vector left exactly as it was. `TryPop` moves an element out rather than copying it, which is how one leaves a vector without being destroyed. `Push` moves its argument in rather than copying it, so a vector is how a sequence of owning elements is built: each is moved in exactly once and destroyed exactly once, when the vector is.
- **`Rux/Collections` `Array<T>` owns what it holds** — the array now takes an allocator at construction and keeps it, implements `Drop`, and is therefore move-only. Destruction destroys every element and then releases the block, in that order, so an array of things that own something no longer leaks what they own; a container destroys an element it does not know is droppable by reading it into a local and letting the local's life end, which is the only mechanism the language offers and costs nothing for an element that owns nothing. `Free` is gone, replaced by the destructor. Constructors are `Filled` and `FromSlice`, both returning the array and reporting the failure through an out-parameter, because the compiler cannot see a write through a pointer as a binding's initialization. Both copy their elements, so an array of a move-only element type has to be built through a `Vector` instead, and the documentation says so. `Vector::ToArray` and `IntoArray` are withdrawn until `Vector` takes an allocator of its own.
- **`Rux/Path` parts, joins and lexical normalization** — `Parent` walks to fixed ends (the root is inside nothing), `FileName` sees through trailing separators, a leading dot is a name so dotfiles have no extension, and one extension comes off the stem. `Normalize` collapses separators, drops `.` and resolves `x/..` — documented as the truth about directories and a lie about symlinks, with the filesystem-true answer deferred to canonicalization.
- **`Rux/Math` exponentials** — `Exp`, `Exp2` and `Expm1` carry their ulp bounds in writing, `Expm1` joins the public surface with a `float32` overload, and a test walks the range reduction by identity rather than by spot values, pins `Exp2` as exact on every integer power in range, and shows `Expm1` keeping a tiny argument that `Exp(x) - 1` loses entirely.
- **`Rux/Math` root accuracy** — `UlpDistance` states floating-point error in the unit error bounds are written in, and `Sqrt`, `Cbrt` and `Hypot` now carry their bounds in writing (0.5, 1 and 1 ulp) with a test that measures them: correct rounding is proven by exact Dekker products rather than asserted.
- **`Rux/Math` rounding modes** — `RoundTiesToEven` completes the five directions beside the existing `Floor`, `Ceil`, `Trunc` and `Round`; `RoundingMode` and `RoundTo` let a direction be named as a value; and `ToIntegerChecked` is the one place a float becomes an integer, reporting when the rounded value does not fit rather than saturating into a plausible wrong number.
- **`Rux/Math` float classification** — `Classify` and the `IsNan`/`IsInfinite`/`IsFinite`/`IsZero`/`IsSubnormal`/`IsNormal` predicates, `SignBit` and `CopySign`, `NextAfter`/`NextUp`/`NextDown`, `ScaleByPowerOfTwo`, `ExponentOf`, `Decompose` and `SplitIntegral`, at both real float widths. Answers come from bit patterns wherever a comparison would lie, so a negative zero keeps its sign and a NaN is recognised rather than slipping through. `float32` stepping uses its own bits, since its neighbours are not its widened value's neighbours.
- **`Rux/Math` integer operations** — `AbsChecked`/`AbsWrapping`, `Minimum`, `Maximum`, `Clamp`, `GcdChecked`, `LcmChecked` and `PowChecked`, generic over the integer type so `int8` and `uint512` run the same code. The fallible ones report `true` on overflow, matching `Core`'s checked arithmetic, and the reason they can fail is one asymmetry: the most negative value of a signed width has no positive counterpart.
- **`Rux/Storage` atomic replacement** — `AtomicWrite` and the one-shot `WriteAtomically` publish a file under its final name in one step: the temporary is created in the target's own directory so the rename stays atomic, and the contents are synced before the rename so the name can never point at data that never arrived. An abandoned or dropped replacement leaves the old contents exactly as they were. Durability of the directory entry itself is explicitly not promised, since Windows cannot sync a directory.
- **`Rux/Storage` temporary files and directories** — names drawn from the entropy source and *claimed* with `createNew` rather than merely chosen, so neither guessing the name nor winning the race is enough; `TemporaryFile` and `TemporaryDirectoryHandle` own both the thing and its name, deleting on `Close` (reported) or on drop (quietly), with `Keep` to hand ownership on.
- **`Rux/Storage` `FileStream`** — `File` no longer implements the stream interfaces directly, because coercing a move-only value into an interface moves it; `file.Stream()` borrows it instead. This also fixes `File` and `DirectoryIterator` destructors that were declared outside a `Drop` implementation and so never ran.
- **`Rux/Storage` locations** — `CurrentDirectory` and `SetCurrentDirectory`, plus the two path resolutions kept deliberately apart: `Absolute` is arithmetic that answers for a path which does not exist, and `Canonicalize` asks the filesystem, resolving every symbolic link and requiring the file to be there. Windows resolves through `GetFinalPathNameByHandleW`; the Unix systems walk components against `readlinkat`, bounded so a link chain that returns to itself is `LimitExceeded` rather than a hang.
- **`Rux/Storage` metadata** — `MetadataOf` and `File::Metadata` report kind, size, link count, permissions and timestamps; `SetPermissions` and `SetTimes` write back what each system accepts. Where the systems disagree the disagreement is reported rather than averaged: `Permissions` carries both the Unix mode and Windows' read-only flag, `CapabilitiesOfSystem` says which is the system's own answer, and a creation time arrives with a presence flag instead of a zero pretending to be a date.
- **`Rux/Storage` copy, rename and links** — `CopyFile` (follows a symbolic link to the bytes), `Rename` (atomic within a volume, replacing an existing target), `CreateHardLink` (does not follow — links the name given) and `CreateSymbolicLink` (stores the target unchecked, so a dangling link is as creatable as a good one). Each follow policy is stated at the call rather than inherited from the platform. `linkat`/`symlinkat` and `CreateHardLinkW`/`CreateSymbolicLinkW` are newly bound across the four platform packages.
- **`Rux/Storage` directories** — `MakeDirectory`, `DeleteDirectory` (empty only), `DeleteFile`, and `ReadDirectory` handing each entry's name back as a lossless `OsString` in the system's own units, dot entries skipped, order the filesystem's. Enumeration goes through `FindFirstFileW`/`FindNextFileW` on Windows and the raw dirent batch calls on the Unix systems — `getdents64`, `getdirentries`, and Darwin's 64-bit-inode entry point, newly bound in the platform packages.
- **`Rux/Storage` files as streams** — `File` implements `Reader`, `Writer` and `Seeker`, so buffering, line reading and binary values stack on a file exactly as on memory; reads and writes are one partial attempt each with the looping left to the shared helpers. `Sync` is the device-acknowledged promise distinct from `Flush`, `Size` measures the open file, and `SetLength` cuts or extends without moving the position.
- **`Rux/Storage` files** — a new package opening the filesystem: `File` owns its handle and closes exactly once (`Close` is the error-visible path, `Drop` the safety net), `OpenOptions` keeps what-may-happen apart from what-happens-to-existence and refuses the contradictions before any platform is asked, and one translation table per platform turns native error codes into the `IoError` kinds a caller acts on, raw code preserved.
- **`Rux/Io` printing and line input return their errors** — every `Print`/`PrintLine` overload returns the `IoError` of the write it made instead of swallowing it, routed through the standard output handle so the console encoding is decided in one place. `ReadLine` appends to a caller's builder and reports `EndOfStream` only for a stream that ends with nothing before it; typed input on a Windows console now arrives as correct UTF-8 rather than code-page text.
- **`Rux/Io` standard streams** — `StandardIn`, `StandardOut` and `StandardError` as byte `Reader`/`Writer` values. Acquisition answers the console-versus-redirection question once: a Windows console reads and writes UTF-16 through its own entry points while a redirected stream carries raw UTF-8, so text is right whether typed, piped or on disk. Nothing is opened and nothing closes on drop — the streams belong to the process. Split characters at read boundaries are carried, never torn.
- **`Rux/Io` binary values** — endian-aware readers and writers for every integer width through `uint512` and both float widths. The caller names the format's byte order and values are assembled arithmetically, so the host's own order never enters into it; floats travel as the IEEE 754 bit patterns of their width. One pair of word functions does the work, and the typed surface reads as what a format stores.
- **`Rux/Io` line reading** — `ReadTextLine` appends the next line of a buffered stream to a builder, without its ending. A line ends at a line feed and a carriage return immediately before it belongs to the ending; a carriage return anywhere else is content. Lines must be UTF-8 (`InvalidText`) and within a named bound (`LimitExceeded`), with the offending line consumed so the caller can report it and read on. A scalar value split across the buffer's edge is completed from the next refill, not condemned.
- **`Rux/Io` buffered reader and writer** — fewer, larger conversations with the machine, both stepping aside for operations already larger than the buffer, and the writer clearing what it gathered before a bypass so order holds. The close contracts differ on purpose: an abandoned reader loses nothing anybody asked for, while the writer's `Drop` flushes as a safety net with the outcome discarded — the explicit `Flush` is where errors are seen. `Buffered`/`Consume` expose the lookahead line reading is built from.
- **`Rux/Io` stream interfaces** — structured `IoError` carrying the shared meaning and the platform's raw code beside it, with the end of a stream in the same type where nobody can lose it; `Reader`, `Writer` and `Seeker` whose honest unit is partial progress; and `ReadExact`/`WriteAll` looping over that honesty, retrying transients and refusing a stream that reports success while moving nothing. Format's text interface is renamed `TextWriter`, leaving `Writer` to mean bytes.
- **`Rux/Path` fallible text conversion and prefixes** — `ToText` is the direction that can fail, for a different reason per platform: Unix bytes may not be UTF-8, Windows units may hold an unpaired surrogate. The prefix family is Windows's own — drive, drive-relative `C:name`, UNC share, verbatim `\\?\` — with the Unix answer being no prefix at all, and no case folding anywhere: `C:` and `c:` are the same drive to the system and different units here, on purpose.
- **`Rux/Path` `Path`, `PathBuffer` and components** — the lexical layer: borrowed structure over native units, a growable owning buffer whose `Push` supplies the separator and lets an absolute segment replace the whole, and a component walk where separator runs count once, a trailing separator adds nothing, and an absolute path opens with an empty root component that tells it from a relative one.
- **`Rux/Path`** — a new package, opening with `OsString` and `OsStringView`: text as the operating system stores it, arbitrary bytes on the Unix systems and arbitrary UTF-16 code units on Windows, unpaired surrogates included. Lossless by construction — whatever name the system hands over survives the round trip — with the conversions asymmetric on purpose: UTF-8 in always succeeds, UTF-8 out will be fallible, because the system's names are under no obligation to be text.
- **`Rux/Time` calendar arithmetic** — days are exact through the epoch count; months and years clamp to the month's end where the day is missing, so January 31st plus a month is the last day of February and the leap day plus a year is the 28th. All of it checked against the four-digit years the text form can spell. IANA zones and local-zone discovery stay deferred: a database with a release cycle is not arithmetic.
- **`Rux/Time` RFC 3339** — the internet profile of ISO 8601, both directions, strict: four year digits, the separators where the shape puts them, nothing after the offset. The leap-second policy is explicit: second 60 parses and folds to the last representable nanosecond of 59, and formatting never writes it, so the fold is one-way and ordinary moments round-trip exactly.
- **`Rux/Time` calendar types** — proleptic-Gregorian `Date` constructible only valid, `TimeOfDay` with the leap second deliberately unrepresentable (a parsing policy, not a value), fixed `UtcOffset` in whole minutes with its sign carried whole, and `DateTime` converting to and from `Timestamp` through the civil-calendar formulas — which round-trip every day count, floor-dividing so a moment before the epoch keeps its time of day positive.
- **`Rux/Time` `Timestamp`** — the UTC wall clock as seconds since the Unix epoch plus a normalized fraction; Windows's 1601-based hundred-nanosecond ticks convert through the one constant the platform package carries. `Since` may answer negative, because the wall clock really jumps backwards — that is information, not an error, and the difference from `Instant`.
- **`Rux/Time` `Instant` and `SleepFor`** — the monotonic clock behind one contract: a later reading minus an earlier one is the time that really elapsed, whatever anybody does to the wall clock, and the reversed pair refuses rather than answering with garbage. Sleep waits out the whole span, going back for the remainder when a signal interrupts it on the Unix systems, and rounding up to the millisecond grain on Windows — at least, never less.
- **`Rux/Time` `Duration`** — a span of time exact to the nanosecond, normalized so the fraction is always in [0, 1e9) with the sign in the seconds: minus one and a half seconds is seconds −2 and half a billion up. Constructors for every unit, truncating totals, and checked add, subtract, negate and scale that refuse at the edges rather than wrapping.
- **`Rux/Unicode`** — a new package: character properties, case, normalization and grapheme segmentation, from tables generated out of the Unicode 17.0.0 Character Database by `Tools/UnicodeGen`, which records the SHA-256 of every input so a regeneration is checkable. Properties answer by binary search over compressed ranges; case is the simple mappings, the unconditional full mappings and locale-independent folding, with the conditional mappings deliberately absent; normalization is all four normal forms with Hangul arithmetic and the blocked-mark rule as UAX #15 states it; graphemes are the UAX #29 rules, emoji joins, flag pairs and Indic conjuncts included. The committed conformance vectors — 1530 rows of the official NormalizationTest and every row of GraphemeBreakTest — run in the ordinary test suite.
- **`Rux/Text` `CString`** — NUL-checked interop with C, in a type of its own so nothing about `String` weakens. Going out, text holding a zero byte is refused rather than truncated, since truncation is how a name that passed a filter and the name C uses part company; coming in, a limit bounds the search for the terminator and the bytes are validated, because nothing about C promises text.
- **`Rux/Text` owning `String` and `StringBuilder`** — a string now owns its block, carries the allocator it gives it back to, and releases itself when it dies; the hand-called `Free` and the leaks it invited are gone. The builder holds well-formed UTF-8 at every moment by refusing anything that is not a whole character, and `IntoString` hands its block over uncopied, remembering the capacity so the allocator gets back the layout it handed out. Search, trim and split moved onto `StringView` and allocate nothing; `Concat`, `Repeat`, `Replace` and the ASCII-only case conversions each allocate exactly once.
- **`Rux/Format` float precision** — `{:.N}` renders N digits after the point, rounded half away from zero with the carry propagating into the integer part. Honoured where the arithmetic can honour it: a value too large to scale into a word renders shortest instead of pretending to a precision it cannot keep.
- **`Rux/Format` float parsing for both widths and the special values** — `NaN`, `Inf` and `-Inf` parse exactly as formatting writes them, so what one side prints the other reads. `ParseFloat32` reads digits at `float64` precision and narrows once at the end; a value the narrow width cannot hold is its overflow rather than a quiet infinity, and one that underflows is the zero it rounds to.
- **`Rux/Format` parsing for every integer width, booleans and characters** — one grammar serves all fourteen integer widths: optional sign, optional base prefix (`0x`/`0o`/`0b`, exactly what formatting writes under `#`), digits. The magnitude accumulates in `uint512` so one loop serves every width, and each width's own bound is checked last — one larger on the negative side, since the most negative value has no positive twin. `ParseBool` is exactly the two words, and `ParseChar` exactly one whole scalar value.
- **`Rux/Format` wide integer formatting** — `int128`/`uint128` through `int512`/`uint512` render in every base and under every spec, through the same digit loop the narrow widths use: wide division is the compiler's, so each width carries only its loop and shares everything after the digits. A `uint512` in decimal is one hundred fifty-five digits and allocates nothing on the way out.
- **`Rux/Format` placeholder specifications** — `{:spec}` carries fill, alignment, sign, alternate form, zero-padding, width, precision and base: `{:>8}` right-aligns, `{:+06}` zero-pads behind a sign, `{:#x}` prefixes hex, `{:.3}` keeps three characters and cuts on a character boundary. The spec belongs to the placeholder but is applied by the value, since base and sign need the bits and not the rendered text — `Display` and `Debug` take it as a parameter, and what every type applies alike (width, fill, alignment) is written once in `WriteAligned`. A spec that does not parse leaves its placeholder as literal text, so the mistake shows where it was written.
- **`Rux/Format` writer-based `Display` and `Debug`** — `Stringable` and its allocate-per-value `ToString` are replaced by two interfaces that write into a `Writer`: what a reader sees, and what an inspector sees, quoted where the two differ. Every primitive renders through a stack buffer and one write, so printing a value allocates nothing at all; `Format` fills `{}` placeholders from `Display` arguments and reports failure through `TextError` instead of dying where it can least be handled. `Rux/Io` prints through the same writer, so a formatted line no longer allocates a string per argument and throws each away.
- **`Rux/Text` UTF-8 and `StringView`** — validation, decoding and encoding done by Table 3-7 of the Unicode standard rather than by the obvious rule, so overlong forms, surrogate halves and values past U+10FFFF are refused structurally instead of checked for afterwards. `StringView` is a borrowed run of bytes that has been checked once, so everything downstream may assume UTF-8 and be right; it indexes in bytes and refuses a cut that is not on a character boundary rather than rounding it.
- **`Rux/Collections` `TreeSet<T>`** — the ordered set over the same red-black kernel, with membership, `First`/`Last`/`Floor`/`Ceiling`, half-open `Range`, three walks, and the full algebra. Elements are the keys of a tree whose values occupy no bytes. The predicates and the shrinking operations allocate nothing; `IntersectWith` and `Subtract` ask for the next element by key rather than by pointer, since removal relinks the nodes around what it removed. `UnionWith` and `SymmetricDifferenceWith` report a `CollectionError` and are not all-or-nothing — a tree has no capacity to reserve up front, and a partial union is a valid set the same call will finish. Kernel queries `Above` and `Below` join it for the strict neighbours.
- **`Rux/Collections` `TreeMap<K,V>` and ordering callbacks** — an ordered map over the red-black kernel: lookup, borrowed and mutable references, `Insert`/`Replace`/`Remove`/`RemoveEntry`, `First`/`Last`, `Floor` and `Ceiling` for the nearest key at or below and at or above a bound, half-open `Range`, and three walks — borrowed, bounded, and consuming. `Comparing` supplies ready-made orderings for the key types `Hashing` covers. A borrow survives insertions and removals of other keys, which a hash map cannot promise, because each entry is its own allocation and removal relinks the successor rather than copying into the removed node.
- **`Rux/Collections` red-black tree kernel** — the ordered counterpart to the Robin Hood table, shared by `TreeMap` and `TreeSet` so the rotations and the two fix-ups exist once. Each node is its own allocation, and removal relinks the successor in place of the removed node rather than emptying one into the other, so an entry that stays keeps the address it had -- which a table, moving entries between slots as it grows, cannot promise at all. Insertion runs at most two rotations and removal at most three, however tall the tree, and a destructive walk frees the nodes iteratively so a tree of a million entries costs no stack.
- **`Rux/Collections` `HashSet<T>` iteration and set algebra** — `Iterate` and `IntoIterator` match the map's. The predicates `IsSubsetOf`, `IsSupersetOf`, `IsDisjointFrom` and `Equals` allocate nothing, and neither do `IntersectWith` and `Subtract`, which only ever make a set smaller. `UnionWith` and `SymmetricDifferenceWith` take room for the worst case first, so they add every element or none — a failure part-way would leave a set that is neither operand nor the answer. `IntersectWith` and `Subtract` sweep the slots until a sweep removes nothing, since removing shifts the following entries into the gap and a chain running past the end of the table shifts them past the end too: the one place having no tombstones costs anything.
- **`Rux/Collections` `HashMap<K,V>` entry, replacement and consuming APIs** — `GetOrInsert` points at the stored value and inserts one only when there is none, which is what an entry API is for without pretending Rux has closures: one probe when the key is present, and the key named once. `Replace` hands back the value that was there, where `Insert` throws it away. `RemoveEntry` hands back both halves, so a key that owns something leaves intact — and it hands back the *stored* key, since a key type carrying anything the equality ignores makes the two different values. `Iterate` gives a `for`-loop iterator over the entries, and `IntoIterator` consumes the map, taking the storage with it and destroying whatever nobody took.
- **`Rux/Collections` Robin Hood table kernel** — `HashMap` and `HashSet` are now one kernel with the set storing nothing alongside its keys, so the probing, the displacement and the deletion exist once. Every entry records its distance from home; an insertion meeting an entry closer to home takes the slot and carries that one onward, which keeps the worst probe near the average and lets a miss stop early instead of scanning somebody else's chain. Removal shifts the following entries back, so **there are no tombstones at all** — the tests churn five hundred insert-remove pairs at a steady size and the capacity never moves. The hash is seeded from `Rux/Entropy` and the ready-made hashers use `SipHash`, which is what stops an adversary who chooses keys from computing collisions and turning every lookup into a scan; the private FNV that was here is gone. Both containers take an allocator, implement `Drop`, and answer with `Option` — `TryGet` and `TryRemove` became `Get` and `Remove`, and a removed value is moved out rather than destroyed.
- **`Rux/Collections` `Deque<T>` owns what it holds** — the deque takes an allocator at construction and keeps it, implements `Drop`, and is move-only; `Free` is gone. `TryPopFront`/`TryPopBack` became `PopFront`/`PopBack` answering with an `Option` and moving the element out, and `At`/`TryGet` became `Get`/`Reference`. Growth is failure-safe in the strongest sense: a fresh block is taken, the elements are relocated into it, and only then is the old one released — so a refused allocation costs nothing, not even the wrapped layout the elements were in. `ShrinkToFit` gives back what rounding leaves spare rather than everything above the length, since the capacity has to stay a power of two for the ring's masking. `AsSlices` still hands out the two runs without moving anything, and `AsSlice` pays a rotation for one.
- **`Rux/Collections` `Vector<T>` insertion, removal and consuming iteration** — `Insert` moves elements along and keeps order; `RemoveAt` closes the gap behind what it took and `SwapRemoveAt` fills it with the last element, constant time against linear, and both hand the element back rather than destroying it. `First`, `Last`, `Slice` and `MutableSliceOf` clamp rather than refuse, so a caller need not check twice. `IntoIterator` consumes the vector and yields each element by value, taking the storage with it and destroying whatever nobody took; `IntoArray` hands the block itself to an array, trimming first because an array's length is its capacity, and reporting rather than leaking when the trim is refused.
- **A match consumes a subject an arm takes apart** — an option matched by value and emptied into a caller's slot was destroyed with its payload still inside it, so the payload had two owners and two destructors. That is what every unwrap in the standard packages did. Only a subject that is a value in its own right is consumed: one read through a borrow has nothing taken from it, and a pattern that binds nothing takes nothing. The arm's binding owns what it took and destroys it when the arm ends, so a payload taken out of an option is destroyed exactly once — by the arm that took it, or by the option if nobody did.
- **Consumption is settled per instantiation** — whether handing a value to a generic consumes it depends on what its type parameter turns out to be, and the question could not be answered where it was asked. Nothing was recorded, so a generic container kept a copy of what it was given and the caller's value was destroyed where it stood: invisible for an element owning nothing, a use-after-free for one owning memory. The question is now recorded where it is asked and answered at every instantiation, and methods and associated functions of generic types are instantiated the same way generic functions already were — none of them were before, so none of their deferred questions were ever asked.
- **`Rux/Collections` shared plumbing** — `CollectionError` gains `Unsupported` and the three questions worth asking of an error, including `IsTransient`, which says that only an allocator's shortage is worth retrying; `FromAllocError` maps an allocator's own answer onto it. New `Storage` helpers talk to an allocator in elements rather than bytes, computing each layout from `sizeof(T)` and `alignof(T)` at the instantiation, so a container that has never seen an element and holds none can still size storage for one — and the layout is computed in one place rather than at every allocation site, which is where a block gets written past its end. `ValueIterator` and `ReferenceIterator` walk a run of elements, the second by pointer so an element that owns something is read without being moved.
- **Allocation-failure and property coverage** — every allocation site in `Rux/Allocator` is now driven through an allocator that refuses on command: a box that cannot be created, an arena that cannot take its first block or its next one, a pool that cannot carve a chunk. The harness counts what it hands out and what comes back, so each case also checks that a failure left nothing behind, which is the failure mode invisible to a test that only reads the error code. Alongside it, every algorithm is checked against a naive implementation of the same thing over pseudorandom sequences at every length from zero to forty-eight — sorting against a selection sort, the bounds against a linear scan, heaps, rotations, partitioning and removal against their own postconditions. The generator is fixed-seed, so a failure is reproducible on every target.
- **`Rux/Algorithms` heaps and folds** — `MakeHeap`, `PushHeap`, `PopHeap`, `SortHeap`, `IsHeap` and `IsHeapUntil`, with `By` forms, arrange a sequence as a max-heap in place with no node structure and no allocation: any sequence a caller already has can be a priority queue. Growing and shrinking stay the caller's — `PushHeap` is told about an element already appended and `PopHeap` leaves the removed one at the end. `Fold` and `FoldRight` state their direction as a contract rather than an implementation detail, since a combine that is not associative gives different answers; `Sum` and `Product` are folds with the function chosen and take their starting value rather than assuming one, because a generic element type has no zero this package could name. `Transform` moved here from `Modify` and now refuses mismatched lengths having written nothing.
- **`Rux/Algorithms` stable sorting** — `StableSort` and `StableSortBy` are a bottom-up merge sort that leaves equal elements in the order they arrived, which is what a second sort pass over a second key needs and what `Sort` does not promise. They ask the caller for scratch as long as the sequence, since this package allocates nothing anywhere, and report false having changed nothing when given less; `RequiredScratch` says how much. Comparisons and moves are O(n log n) for every input — there is no bad case. The merges alternate between the sequence and the scratch, so nothing is copied merely to move it back, and the answer is copied home only when an odd number of passes leaves it in the scratch. `NthElement` and `PartialSort` gained the documentation the rest of the package has, including that selection is linear on average and what it does not order.
- **`Rux/Algorithms` sorting takes views and states its worst case** — `Sort`, `SortDescending`, `NthElement`, `PartialSort` and their `By` forms take a `MutableSlice<T>`, and every `By` form in the package now takes a three-way comparison rather than a less-than. The guarantees are written down rather than implied: O(n log n) comparisons for every input with nothing probabilistic about it, O(1) auxiliary storage, and O(log n) stack frames because the recursive call always takes the smaller side of a partition while the loop handles the larger. Sorting is not stable and says so, next to why — a caller who needs equal elements to keep their order needs somewhere to put things.
- **`Rux/Algorithms` mutations take views** — `Reverse`, `Rotate`, `Fill`, `Unique`, `RemoveValue`, the renamed `RemoveWhere` and `Partition` take a `MutableSlice<T>`, and `PartitionPoint` a `Slice<T>`. `Copy` became `CopyTo` and gained `MoveTo`, which copies back to front where the two overlap the other way — the pairing `Rux/Memory` already has for bytes, now for elements. Both refuse mismatched lengths having written nothing, since a partial copy is worse than a refused one when the caller cannot tell how far it got. `Rotate` is three reversals and needs no scratch storage. What a removal leaves past the count it reports is documented as unspecified rather than left to be discovered, and `Partition` says outright that it is unstable.
- **`Rux/Algorithms` ordered searches take slices and answer with `Option`** — `IsSorted`, `IsSortedUntil`, `LowerBound`, `UpperBound`, `EqualRange` and the renamed `BinarySearch` now take a `Slice<T>`, and the `By` forms take a three-way comparison instead of a less-than. A binary search that finds several equal elements reports the first of them, so the answer depends on the sequence rather than on how the search divided it; equality is the ordering's rather than the type's, which is what makes a comparator that reads one field behave predictably. The test checks every bound against a linear count of the equal elements, at a value before everything, after everything, absent between two present ones, present once and present many times, over an empty slice, a one-element slice and a sixty-four element one.
- **`Rux/Algorithms` queries take slices and answer with `Option` and `Ordering`** — `Find` and `MinMax` now take a `Slice<T>` instead of a pointer and a length, and a search answers with the index it found wrapped in an `Option` instead of a `bool` and an out-parameter: not found is an ordinary outcome, and a sentinel index is a bug waiting for a long enough sequence. Comparison joins them: `Compare` and `CompareBy` order two sequences lexicographically and answer with `Ordering`, and the `By` forms throughout take a three-way comparison rather than a less-than. Renames follow the new shapes — `TryFind` to `IndexOf`, `TryFindLastIf` to `LastIndexWhere`, `All`/`Any`/`None` to `AllOf`/`AnyOf`/`NoneOf`, `Equal` to `SequenceEqual`. Ties go to the earliest index at both ends, stated as a promise rather than left to chance, and an empty slice has no extreme at all rather than a default one. `Modify`, `Search` and `Sort` still take a pointer and a length.
- **`Rux/Hash` keyed SipHash-2-4** — the hash for a table whose keys someone else chooses. Every other hash in the package has a public structure, so colliding inputs can be computed and fed to a table until every lookup is linear; SipHash is keyed, so without the key finding a collision is as hard as breaking the function. The key is a secret drawn from `Rux/Entropy` at startup, since a key compiled into a program is a published key. Checked against the paper's own vectors at the lengths either side of a word boundary, where a mishandled tail shows, and streamed in every possible pair of pieces. The length is mixed into the final word, so a message padded with zeroes is not the same message — checked directly, because an implementation that forgot it would pass every other test here.
- **`Rux/Hash` xxHash64** — seeded, streaming and one-shot, matching the reference implementation for every input length and every seed. Four independent accumulators consume thirty-two bytes a round, so a wide machine has four chains to run at once instead of one to wait on, and the mixing is arithmetic rather than table lookup, so there is no table to evict on data that does not fit in cache. Input that does not fill a block is held until the rest arrives: the test writes a long input back in every possible pair of pieces, and one byte at a time, and each has to agree with hashing it at once. The seed is part of the algorithm — two seeds give unrelated answers for the same input, which stops accidental collisions from following data between tables, though not deliberate ones.
- **`Rux/Hash` CRC-32 and CRC-32C** — both in the reflected, table-driven form every implementation uses, so a value computed here matches gzip, PNG and zip for `Crc32`, and iSCSI, ext4, Btrfs and SCTP for `Crc32c`. The polynomials and the 256-entry tables are part of the surface, and the test recomputes every entry the slow way rather than trusting a block of plausible constants. The initial all-ones register and the final complement are what make a message padded with zeroes at either end give a different answer from the message itself, which the test checks directly. A CRC detects accident and never intent — producing a message with a chosen CRC is arithmetic a beginner can do — so these implement `Hasher` because feeding them bytes has the same shape, not because they substitute for one.
- **`Rux/Hash` contracts and FNV-1a** — every hash in the package is built the same way: make one, write bytes in order, ask for the answer, which is what lets a value be hashed without first being flattened into a buffer. `Hasher` is the contract, and it is meant to be a generic bound rather than an interface value: a bound takes the caller's own hasher by pointer, while coercing one to an interface would take a copy and leave the caller's hasher where it started. `WriteUint32` and `WriteUint64` use a fixed byte order rather than the machine's, so a value hashes the same on every target. FNV-1a arrives in both published widths, incremental and one-shot, and agrees with any other correct implementation — splitting the writes changes nothing, finishing does not consume, and the empty input gives the specified offset basis rather than zero. The `Md5`, `Sha256` and `Sha512` placeholders are gone: those belong to `Rux/Crypto`, and this package is the non-cryptographic set.
- **`Rux/Entropy` portable `Fill` facade** — `FillFrom` splits a request larger than a single call accepts, zeroizes the whole buffer when any part of it fails, and reaches the generator through an `EntropySource` rather than by name. That last part is the point: entropy failures need a kernel with no generator or a provider that refuses, so a test supplies a source that fails on demand and the code handling the failure is the same code in the test and in production. `SystemEntropy` is the real source as an interface value, `FillWithRetries` retries only what says retrying might work, and `NextUint64` draws the seed a generator wants — returning zero on failure and scrubbing its own local, so a caller who ignores the error gets a value they will notice.
- **`Rux/Entropy`** — a new package that does one thing: fill a buffer with bytes an adversary cannot guess. Four systems offer four interfaces, and one `EntropyError` covers all of them. Linux and FreeBSD have a `getrandom` call that may write fewer bytes than asked for and may be interrupted by a signal, so filling a whole buffer means looping; an interruption is retried a bounded number of times and then reported as `Interrupted` rather than spun on forever, and a kernel without the call reports `Unsupported`. Darwin's `arc4random_buf` is seeded before any user code runs and cannot fail. Windows' `BCryptGenRandom` fills the whole buffer or fails, and takes a 32-bit count, so a larger request is refused as `TooLarge` rather than truncated — checked before the buffer is looked at, so an impossible request is refused whatever came with it. A failure leaves nothing usable behind: whatever a short read managed to write is zeroized first, because a half-filled key looks exactly as random as a whole one, and a caller who ignores the result should get an obviously wrong buffer rather than a subtly weak one.
- **`Rux/Allocator` `FixedBuffer` and `Pool`** — two allocators that do not go to the system. `FixedBuffer` hands out storage the caller already has and reports `OutOfMemory` rather than asking for more, which is what the places where allocation must not happen need; it owns nothing and has no destructor, but it is used through a handle because an allocator copied while in use would hand out the same storage twice. `Pool` serves small blocks from five power-of-two size classes, each with its own free list, so allocation and release are a pointer swap with no search and no coalescing; a class that runs dry carves one chunk from a backing allocator, and a released block is the very next one handed out. Rounding up is what pays for the speed — a 17-byte request occupies a 32-byte block — and a request no class can serve goes straight to the backing allocator, decided from the layout alone so a release reaches the same conclusion as its allocation without the pool recording anything per block. `Reset` on a pool takes every block back while keeping the chunks, so a second round of the same work asks the backing allocator for nothing.
- **`Rux/Allocator` `Arena`** — a block-based bump allocator that reclaims everything at once. Blocks come from a backing allocator and each is twice the size of the last, so a long-lived arena stops going back to the system; a request larger than a block gets one of its own. `Reset` rewinds every allocation while keeping the largest block, so a second round of the same work asks the system for nothing. The arena owns its blocks and so implements `Drop`, which makes it move-only — and coercing a move-only value to an interface moves it, leaving the owner unable to reset what it no longer has. `Arena::Handle` is the answer: a `Copy` borrow that implements `Allocator` while the arena stays where it is. A release is accepted rather than refused, so an arena can stand in for any allocator; the most recent allocation is rewound, and growing it extends in place.
- **`Rux/Allocator` `Box<T>`** — one heap value with exactly one owner. It implements `Drop`, so it is move-only: handing one to a function or another binding transfers it, and reading the source afterwards is rejected while compiling. The allocator is held as an interface value rather than a type parameter, so a container of boxes need not name which allocator each came from. A box is returned rather than written through an out-parameter, because the compiler tracks a binding's initialization and a write through a pointer is invisible to it — a box delivered that way would be owned by a binding believed to own nothing; the error is what travels by pointer instead. A failed creation gives an empty box that owns and releases nothing, and `TryTake` moves the value out and releases the storage there and then.
- **`Rux/Memory` raw block operations redesigned** — `Move` is new and is defined for every overlap, which `Copy` is not; `Equal`, `MismatchOffset` and `Find` join it. `Compare` now returns an `Ordering`, which is what the package documentation always claimed it returned while the implementation returned a first-difference offset — that offset is `MismatchOffset` now, and `Equal` is what every caller of the old `Compare` actually wanted. Zero length is legal everywhere and null is legal with it, so `Copy(null, null, 0)` is defined and does nothing, which is deliberately not C's rule. `Set` takes its arguments in `memset` order and its value as a `byte`, so a call written the old way fails to compile rather than filling the wrong length.
- **`Rux/Windows` split, and given its Unicode, virtual-memory, entropy and precise-clock surfaces** — one 487-line file becomes `Types`, `Constants`, `Kernel`, `File`, `Memory`, `Entropy` and `Clock`. `Types` names what Win32 names: `Handle`, `Bool` (a 32-bit integer, not a byte), `NtStatus`, `WideChar`, and the `InvalidHandleValue` that a handle-returning call reports failure with — which is not the null a memory-returning call reports. `File` declares the `W` entry points, which are the only ones that carry every name a file system can hold; the `A` forms convert through the process code page and are now marked as such. `Memory` declares the reserve-and-commit interface no other supported system has. `Entropy` declares `BCryptGenRandom` behind a `GetRandom` that either fills the buffer or fails, with no short count to loop over. `Clock` declares the monotonic performance counter and the precise wall clock, with the constants that convert 1601-based ticks to the Unix epoch.
- **`Rux/macOS` moved off direct system calls onto the libSystem ABI** — the package issued its own `syscall` and `svc` instructions with Darwin trap numbers, which Apple does not support: the numbers are private, they have changed between releases, and on Apple Silicon the trap interface is not reachable from ordinary code. Every call now goes through a libSystem entry point declared under the symbol it exports. The package is split into `Types`, `Errors`, `LibSystem`, `File`, `Memory`, `Clock`, `Entropy`, `Process` and `Dynamic`; `Normalize` folds libSystem's `-1`-and-`errno` reporting into the negative-error convention the Linux and FreeBSD packages use, so `IsError` and `Errno` read the same on all three. `Brk` is gone, having never been callable from 64-bit Darwin code, and the file, clock, entropy and dynamic-loading surfaces are filled in.
- **`Rux/FreeBSD` split into domain modules and completed** — one 306-line file becomes `Types`, `Errors`, `Syscall`, `File`, `Memory`, `Clock`, `Entropy`, `Process`, and `Dynamic`, matching the Linux package's shape. `OpenAt`, `Lseek`, `Fsync`, `Ftruncate`, `UnlinkAt`, `MkdirAt`, `RenameAt`, `Fstat`, `Dup2` and `Pipe2` join `File`; `Mprotect` and `Madvise` join `Memory`; `ClockGetResolution` joins `Clock`; `Entropy` and `Dynamic` are new. The documentation names where FreeBSD and Linux differ despite looking alike: monotonic is clock 4 here and 1 there, the open flags are the BSD ones, `MADV_DONTNEED` does not discard where Linux's does, and only the errno numbers below thirty-five agree.
- **`Rux/Linux` file, memory, entropy and clock wrappers completed** — `OpenAt`, `Lseek`, `Fsync`, `Ftruncate`, `UnlinkAt`, `MkdirAt`, `RenameAt`, `Fstat`, `Dup3` and `Pipe2` join `File` with the open flags and seek origins; `Mprotect` and `Madvise` join `Memory`; `ClockGetResolution` and `ClockNanosleep` join `Clock`; and a new `Entropy` module declares `GetRandom`. Only calls both architectures have are wrapped: AArch64 never got `open`, `stat`, `unlink`, `mkdir`, `rename`, `dup2` or `pipe`, so the `*at` forms are what this package offers and `AtFdCwd` is what makes an ordinary path work through them.
- **`Rux/Linux` split into domain modules** — one 283-line file becomes `Types`, `Errors`, `Syscall`, `File`, `Memory`, `Clock`, `Process`, and `Dynamic`, each documented to the contract. `Types` names the kernel ABI's own types; `Errors` gains the errno numbers under the kernel's own spelling, beside the `IsError` and `Errno` that read a raw result; `Dynamic` is new, declaring `dlopen`, `dlsym`, `dlclose` and `dlerror` with the `RTLD_*` flags, and is the one part of the interface that is a library call rather than a system call. `Read` now takes a `*var opaque`, since it writes what it is given.
- **`Rux/C` time ABI corrections and math completion** — `clock_t` was declared a fixed 64-bit integer and is a `long`, which the Universal CRT makes 32 bits, so reading one on Windows took in four bytes of whatever followed the result; it now follows each target, and Darwin's unsigned spelling with it. `timespec.tv_nsec` had the same defect and mattered more: a nanosecond count filled in by the runtime read four bytes of stale padding as its upper half, which a test proved before the fix. C11's `timespec_get` is declared under the name each platform publishes — the Universal CRT exports only `_timespec64_get` — behind a `TimespecGet` that picks between them, with `TIME_UTC` and `CLOCKS_PER_SEC` beside it. `scalbln` and `scalblnf` join `Math` with the `long` exponent they take, along with `HUGE_VAL`, `HUGE_VALF`, `INFINITY` and `NAN`; the calls that hand back storage the runtime owns — `asctime`, `ctime`, `gmtime`, `localtime` — now say so.
- **`Rux/C` curated stdlib and stdio** — the numeric conversion family (`strtol`, `strtoul`, `strtoll`, `strtoull`, `strtod`, `strtof`), `qsort`, `bsearch`, and `_Exit` join `StdLib`, each conversion returning the C type it actually returns: `strtol` gives a `c_long`, which is 32 bits on Windows and 64 elsewhere. Both modules gain their constants — `EOF`, the three seek origins, the three buffering modes, `BUFSIZ`, `FOPEN_MAX`, `FILENAME_MAX`, `L_tmpnam`, `TMP_MAX`, `EXIT_SUCCESS`, `EXIT_FAILURE`, and `RAND_MAX` — with the values each target's own header defines. What is dangerous is now marked where it is declared: `gets` is not declared at all, the `ato*` conversions each point at the `strto*` one that can report failure, and `sprintf`, `scanf`, `tmpnam`, `system` and `rand` each say what they will not protect the caller from.
- **`Rux/C` curated stdlib and stdio** — the numeric conversion family (`strtol`, `strtoul`, `strtoll`, `strtoull`, `strtod`, `strtof`), `qsort`, `bsearch`, and `_Exit` join `StdLib`, each conversion returning the C type it actually returns: `strtol` gives a `c_long`, which is 32 bits on Windows and 64 elsewhere. Both modules gain their constants — `EOF`, the three seek origins, the three buffering modes, `BUFSIZ`, `FOPEN_MAX`, `FILENAME_MAX`, `L_tmpnam`, `TMP_MAX`, `EXIT_SUCCESS`, `EXIT_FAILURE`, and `RAND_MAX` — with the values each target's own header defines, keeping their published spelling. What is dangerous is now marked where it is declared: `gets` is not declared at all, the `ato*` conversions each point at the `strto*` one that can report failure, and `sprintf`, `scanf`, `tmpnam`, `system` and `rand` each say what they will not protect the caller from.
- **`Rux/C` byte-string, memory, and allocation declarations** — a new `String` module covers `<string.h>`: `memchr`, `memcmp`, `memcpy`, `memmove` and `memset`, and the terminated family from `strlen` and `strcmp` through `strstr`, `strspn`, `strxfrm` and `strtok`. Each records what it requires of its arguments and the trap worth naming — `strncpy` does not terminate a source that fills the count, `strcat` is quadratic when repeated, `memcmp` stops at the first difference and so must not compare secrets. Allocation is restated against the ABI types: `malloc`, `calloc` and `realloc` take and return `size_t` and `*var opaque`, and C11's `aligned_alloc` is declared where it exists, with Windows getting `_aligned_malloc` and `_aligned_free` instead — arguments the other way round, and a release that must match.
- **`Rux/C` ABI types, `errno` access, and opaque handles** — a new `Types` module gives the C ABI its own spellings: `c_char` and its explicit-signedness siblings, `c_short` through `c_ulonglong`, `c_float`, `c_double`, `c_bool`, and the pointer-sized `size_t`, `ssize_t`, `ptrdiff_t`, `intptr_t` and `uintptr_t`. `c_long`, `c_ulong` and `wchar_t` follow the target's data model, which is the thing a binding cannot assume. `FILE` and `fpos_t` are declared with no fields, so a stream is a `*FILE` rather than a `*opaque` and cannot be passed where another handle was meant; `StdIo` is rewritten against them. `errno` is reached through whichever accessor the platform exports — `__errno_location`, `__error` or `_errno` — wrapped by `ErrnoLocation` and `errno`, with the three error numbers C mandates.
- **`Core` diagnostics, metadata, and ranges documented as one surface** — `Assert`, `DebugAssert`, `Panic`, `#Error`, and `#Warn` are collected into one `Diagnostics` module, stating what each costs at run time and that neither `Assert` nor `Panic` unwinds, so nothing released on a failing path may be left to a destructor. `#target`, `#build`, `#compiler`, `#config`, and `#source` and every enum they are typed by now document each variant and field — which of `long`'s two widths a data model means, why a feature query is preferable to a version comparison, and that a build timestamp identifies the build rather than measuring time. The six range types document which ends they close over and that they carry bounds and no methods, because a range type resolves to the compiler's built-in form rather than to its declaration.
- **`Core` checked conversion and float classification** — `ConvertChecked`, `ConvertWrapping`, `ConvertSaturating`, and `IsSignedType`, plus `IsNaN`, `IsZero`, `IsInfinite`, `IsFinite`, `IsNegativeZero`, `IsSignNegative`, `IsSignPositive`, and `SignOf`. A conversion is checked by a round trip in the source type, so nothing compares a value of one type against a value of another, plus one test for the pair a round trip cannot see: a value and its conversion that disagree in sign, which is how `-1` reaches `uint64` and `2^63` reaches `int64` while converting back to what they started as. A float source needs no special case, since a NaN never equals itself and an infinity converts back to something finite. The classification predicates are arithmetic rather than bit inspection, so one implementation serves every float width including the software-lowered ones; the sign of a zero, which comparison cannot see, is read from the infinity it divides into.
- **`Core` interfaces for generic code** — `Drop`, `Equatable`, `Comparable`, `Hashable`, `Iterator`, and `Iterable` are published as the bounds generic packages write. `Equatable` and `Comparable` use `Self` so an operand is the implementing type rather than the interface, and `Comparable` reports an `Ordering`. `Hashable` documents the one rule that matters — equal values hash the same — and that a hash is not stable across runs, so nothing outliving the process should be keyed on one. `Iterator` and `Iterable` name the protocol the compiler already drives by shape (`Next` returning an `Option`, `Iterate` returning an iterator); they record intent rather than carrying the methods, since an interface cannot name the item type its implementor chooses. `Drop` marks a type move-only, which is enforced today, and its body is run at every destruction point.
- **`Core` value outcomes** — `Option<T>`, `Result<T, E>`, `Unit`, and `Ordering` are implemented together as one set. `Option<T>` carries an absence that needs no explanation and `Result<T, E>` a failure that does; `Unit` fills the type position of an operation with nothing to report; `Ordering` is a three-way comparison stored as `-1`, `0`, or `1` in an `int8`. Asking which case an outcome holds borrows it, so the outcome is still the caller's; reaching a payload consumes it, so a move-only value can never end up with two owners. A `Try*` extraction refuses a null destination and leaves it unwritten while still consuming the outcome, and a fallback that goes unused is dropped rather than leaked.

- **`Rux/Algorithms`** — the package is implemented, replacing its reserved placeholder. Five modules split by what they ask of the element type, so a type defining one comparison operator can still use the modules that want it: `Modify` (`Swap`, `Reverse`, `Rotate`, `Fill`, `Copy`, `CopyBackward`, `Unique`, `RemoveValue`) needs nothing; `Find` (`Contains`, `Count`, `TryFind`, `TryFindLast`, `Equal`, `TryMismatch`) needs `==`; and `Search` (`IsSorted`, `IsSortedUntil`, `LowerBound`, `UpperBound`, `TryBinarySearch`, `EqualRange`), `Sort` (`Sort`, `SortDescending`, `NthElement`, `PartialSort`), and `MinMax` (`TryMinIndex`, `TryMaxIndex`, `TryMinMaxIndex`, `Clamp`) need `<`. Ordering comes from the `<` operator rather than a comparator parameter, so every primitive works and a struct joins in by defining `func <`. `Sort` is an introsort — quicksort with a three-way partition, falling back to heapsort on its recursion budget and to insertion sort below sixteen elements — giving O(n log n) worst case, linear behavior on all-equal input, and about log2(n) stack frames. Nothing in the package allocates, its only dependency is `Rux/Core`, and every entry point takes a pointer and a length so it accepts a `Slice`, a `MutableSlice`, an `Array`, a `Vector`, or a `Deque` view without coupling to any of them.
- **Comparator-taking algorithms in `Rux/Algorithms`** — every ordering function gains a `*By` counterpart taking an explicit comparator: `SortBy`, `SortDescendingBy`, `NthElementBy`, `PartialSortBy`, `IsSortedBy`, `IsSortedUntilBy`, `LowerBoundBy`, `UpperBoundBy`, `TryBinarySearchBy`, `EqualRangeBy`, `TryMinIndexBy`, `TryMaxIndexBy`, `TryMinMaxIndexBy` and `ClampBy`. The comparator answers the same question `<` does and must be a strict weak ordering; equivalence is derived from it alone, so a comparator is enough on its own and the element type need not define any operator. They are separate names rather than overloads because Rux resolves an untyped integer literal against a single candidate but not against an overload set, so an overload would have stopped existing calls like `Sort<int32>(data, 8)` from compiling.
- **Predicate-taking algorithms in `Rux/Algorithms`** — `TryFindIf`, `TryFindLastIf`, `CountIf`, `All`, `Any` and `None` query a sequence against a caller's test rather than a value, and `RemoveIf`, `Partition`, `PartitionPoint`, `Transform` and `Fold` act on one. These ask nothing of the element type at all — the predicate supplies the test — so they work on any element whatsoever, where the value-based queries need `==` and the ordered ones need `<`. `Transform` and `Fold` let the result type differ from the element type, so a fold both sums a sequence and builds something else out of one. `Partition` does not preserve order within either group, while `RemoveIf` does. A predicate is a plain function value and carries no captured state, since Rux has no closures.
- **`Core::MutableSlice`** — the writable counterpart to `Slice`, holding `*var T` where `Slice` holds `*T`, with `New`, `From`, `Length`, `IsEmpty`, `At`, `Set`, `Swap`, `Sub`, and `AsSlice`. It borrows and never owns. `Sub` clamps a length that runs past the end and yields an empty view for a start at or past it, so a sub-view never covers storage the original does not.
- **`Rux/Collections`** — the package is implemented, replacing its partial surface and its reserved placeholders. `Array<T>` is fixed-length owned heap storage; `Vector<T>` is the growable contiguous sequence, and the stack; `Deque<T>` is a double-ended queue over a circular buffer, and the queue; `HashMap<K, V>` and `HashSet<T>` are open-addressed tables with linear probing, a three-quarters load factor and tombstones. Every operation that allocates reports a `CollectionError` (`None`, `OutOfMemory`, `CapacityOverflow`, `IndexOutOfRange`) and leaves the container unchanged when it fails, while operations that cannot allocate report an ordinary miss with a `bool` through the `Try*` and out-parameter convention — so an exhausted allocator is never confused with an empty container, a missing key, or a rejected index. Every count is checked for overflow before anything is allocated, and a reallocated block lands in a local before it replaces the owned pointer, so a failure can no longer leak the old allocation. Because Rux has no trait system and no closures, the hash tables take hash and equality function values and hold them for the life of the table, the `Hashing` module supplies ready-made pairs for the common key types, and traversal is a cursor rather than a callback.
- **`AsMutableSlice` across `Rux/Collections`** — every container hands out a writable view of its elements without copying them, mirroring `AsSlice`. `Vector` exposes only its initialized elements, never its spare capacity, and `Deque` adds `AsSlices` for the two runs of a wrapped ring plus `MakeContiguous` to rotate them together.

#### CLI / Package Manager

- **`rux doc`** — generates deterministic, self-contained HTML API documentation after the normal compiler frontend and semantic analysis succeed. Outer `///` comments support a safe Markdown subset, target and define selection match `rux check`, public API is the default, `--document-private-items` includes private declarations, and managed-directory markers prevent `--output` from replacing unrelated files.
- **Versioned CLI contract** — `rux help --json` and `rux help <command> --json` publish schema version 1 for documentation tooling, with the program version, global options, command usage, arguments, options, examples, and stable documentation URLs.
- **Cross-target builds** — a `--target <triple>` naming something other than the host is no longer refused by target-aware commands. Machine code and executables are produced entirely in-process for both architectures, so a Linux host writes a Windows PE, a macOS Mach-O, or an AArch64 Linux ELF with no external toolchain and no change in output for the host triple. What a target needs is a writer for its object format rather than a machine of its own kind: x86-64 reaches every supported operating system, while AArch64 reaches Linux ELF and Windows PE/COFF; AArch64 Mach-O and non-Linux ELF targets are refused with a diagnostic naming the triple until their image writers exist.
- **Host-only `rux run` and direct target tests** — `rux run` always builds the compiler process's host triple and no longer accepts `--target`. `rux test --target` executes only when the target OS matches the host and its architecture equals the compiler process or native OS architecture, preserving x86-64-compiler acceptance on Windows ARM and under Rosetta without selecting an emulator. Other cross targets fail before suite compilation and direct users to `rux build --target` or `rux check --target` plus testing on a native machine.
- **Per-target output directories** — a build for a target other than the host writes to `<Output>/<Profile>/<triple>/`, so building the same package for several targets no longer has each one overwrite the last. The host target keeps the `<Output>/<Profile>/` path it has always had, and a host build is byte-identical whether the triple is named explicitly or left out. Artifact names follow the target operating system rather than the host, so a Linux host produces `Name.exe` for `windows-x86_64` and `libName.dylib` for a macOS shared library. `rux build --stats` names the target it built for, and the one-line summary mentions it whenever it is not the host.
- **`rux publish` and `rux pack`** — publication transport, the write half of the registry contract. `rux pack` builds the package archive, a ZIP named `<Name>-<Version>.ruxpkg` holding `Rux.toml` at its root, every file below `Src/`, and the files named by `ReadmeFile` and `LicenseFile`; entries are sorted and carry a fixed timestamp, so packing one tree twice produces identical bytes. `rux publish` uploads that archive together with the exact manifest bytes it embeds. The bearer credential comes from `RUX_TOKEN` or from `rux login`, and never from a flag, keeping it out of shell history and the process list; `RUX_REGISTRY_URL` or `--registry <url>` selects the registry, and `--dry-run` validates and packs without uploading. The registry's RFC 9457 problem responses are reported as ordinary CLI errors, so an immutable-version conflict, an unclaimed namespace, or a token missing the `publish` scope each explain themselves. The matching read half is described under **Changed**: `rux install` now resolves and downloads through the same registry.
- **`rux login` and `rux logout`** — store a registry credential once instead of exporting `RUX_TOKEN` for every publish. The token is read from stdin, never from an option, so it stays out of shell history and the process list; a terminal is prompted without echo, and any other stdin is read as one line, so `echo "$TOKEN" | rux login` works. Tokens are stored beside the package cache in `%LOCALAPPDATA%\Rux\Credentials.toml` (`$HOME/.rux/credentials.toml` elsewhere), restricted to the owner and written through a temporary that is locked down before the token reaches it. Entries are keyed by registry base URL rather than kept as one ambient token, so retargeting `--registry` at a local registry cannot leak the credential for the official one, and `rux logout` removes just the selected registry's entry. `rux login` verifies the token against the registry first and refuses one that is rejected; a registry that cannot be reached or does not implement the check warns and stores it unverified. `RUX_TOKEN` still takes precedence over a stored token, so CI is never shadowed by a file left on a self-hosted runner, and `rux publish` now names whichever source actually supplied the credential when the registry rejects it.
- **Manifest publication validation profile** — the profile documented for Version 1 is now enforced. `rux publish` and `rux pack` reject a workspace manifest, a missing `Namespace` or `MinRux`, a `MinRux` below `0.4.0`, and every path dependency before any archive is built or any request is sent; every other command keeps the permissive local profile. First-party packages now declare `MinRux = "0.4.0"`, and the repository manifest-policy test holds them to the publication profile.
- **Compile-time configuration** — `[Build.Defines]` supplies string values to `config`, and `--define NAME[=VALUE]` overrides them for `build`, `check`, `run`, and `test`. Date/time compiler parameters share one UTC build timestamp and honor `SOURCE_DATE_EPOCH` for reproducible builds.
- **Manifest-less workspace installation** — bare `rux install` now discovers package manifests below the root `Tests/` tree, immediate member packages, and member `Tests/` trees when no root `Rux.toml` exists. Registry dependencies are deduplicated and installed through the existing transitive resolver, so repository test setup no longer needs a hard-coded package list.
- **`rux uninstall --global`** — remove every package from the global cache, whether or not the current `Rux.toml` declares it. Completes the `--global` set alongside `rux list --global` and `rux update --global`.

#### Runtime / Linker

- **Native AArch64 back end** — `linux-aarch64` programs are now compiled the way `linux-x86_64` programs always were, with no external tool anywhere in the pipeline. A new AArch64 instruction encoder writes instruction words directly — the data-processing, load/store, branch, system, and scalar floating-point families, plus the composite sequences a code generator reaches for constantly, such as the shortest `MOVZ`/`MOVK` chain for a 64-bit constant and the `ADRP`/`ADD` pair that forms a symbol address. The code generator lowers LIR through the same shared record layout, phi resolution, and linear-scan allocation the x86-64 back end uses, follows AAPCS64 for arguments, returns, indirect results, variadics, and callee-saved registers, and hands the result to the same RCU object model. Both back ends are now symmetric file for file, and `Docs/Architecture.md` shows the single pipeline they share.
- **AArch64 ELF executables, shared libraries, and objects** — the ELF writer takes the target architecture rather than assuming x86-64: it stamps `EM_AARCH64`, separates segments by the 64 KB alignment an AArch64 image requires, writes the AArch64 entry preamble and PLT stubs as `ADRP`/`LDR`/`ADD` sequences, and resolves the split-immediate relocation kinds — `CALL26`, `JUMP26`, `CONDBR19`, `TSTBR14`, `ADR_PREL_PG_HI21`, `ADD_ABS_LO12_NC`, the width-specific `LDST*_ABS_LO12_NC`, `MOVW_UABS_G0` through `G3`, `PREL32`, and `PREL64` — by patching instruction fields rather than whole words. Dynamic images record `DT_NEEDED` and `/lib/ld-linux-aarch64.so.1` without opening a host library, so a cross link needs no sysroot; `GLOB_DAT` and `JUMP_SLOT` entries let an AArch64 program import from a shared library, and a `StaticLibrary` package's `.o` members are real `ET_REL` objects with relocation sections an external linker accepts.
- **AArch64 inline assembly** — an `asm func` body in an AArch64 build is parsed with the AArch64 register table and assembled to machine code by Rux itself, covering the mnemonics the encoder implements together with the operand syntax the architecture uses: `#imm` immediates, `[Xn, #off]`, `[Xn, Xm, LSL #3]`, the pre- and post-index forms, shifted register operands, and `B.<cond>`. Local labels, calls to other Rux functions, and raw `svc` system calls all work as they do on x86-64, and `Tests/Language/AsmAArch64/` exercises arithmetic, memory, every branch form, and two system calls.

### Changed

#### Language
- **`String` is a name like any other** — the compiler sized any type named `String` at sixteen bytes and resolved the name to a built-in kind, so `Rux/Text`'s `String` had to be exactly a pointer and a length. A string that owns its bytes must carry the allocator it gives them back to, which is sixteen bytes more, and the compiler would have gone on laying out half the value that was there. Nothing needed the special case: string literals are `Slice<char8>` and always were, and the built-in kind was produced by nothing but that name being resolved. The kind, its constructor and every branch handling it are gone.

- **Explicit binding and pointee mutability** — `let` bindings and parameters are immutable by default, while `var` declares a mutable binding or parameter. Pointer pointee mutability is written `*T` (read-only) or `*var T` (writable), and `@place` infers the pointer form from the addressed place. This replaces `let mut`, `*mut T`, and `@mut`.
- **Method receivers carry a written type** — a receiver is an ordinary parameter named `self`, and its type says how the method takes it: `self: *T` reads the receiver, `self: *var T` writes it in place, and `self: T` takes a copy (`var self: T` for a copy the method may rewrite). The receiver names the type being extended, comes first, and belongs to a method; an extend block implementing an interface needs a receiver that arrives as an address, since a vtable slot is handed one. A bare `self` no longer parses — it meant a writable pointer whatever the method did with it, which is the one thing about a method a signature could not state. Writes through the receiver are now checked like any other write, so a method that writes needs `*var`, and so does a call site handing one a receiver: a read-only pointer or a `let` binding is refused where a writable receiver is required. This closes a hole that reached past methods, where a function taking `builder: *StringBuilder` could append through a read-only pointer.
- **Fully-qualified item imports** — importing an item now requires its complete `Package::Module::…::Item` path; the shortcut that let a bare `import Package::Item` reach into a package's same-named module is gone. `import Memory::Alloc` is an error (with a `did you mean 'import Memory::Memory::Alloc'?` hint) — the package name is always the first segment and the containing module must be named. Items declared at a package's root (`import Core::{ #target }`) are unaffected.
- **Extern import syntax** — `#Link("Kernel32.dll")` imports an extern function under its Rux declaration name, while an optional second argument such as `#Link("Kernel32.dll", "Beep")` names a different exported DLL symbol. The one-argument form also applies a library to an extern block. `#Library` and `#Symbol` remain compatibility spellings but cannot be combined with `#Link`.
- **`#`-prefixed compiler context and canonical target variants** — compiler-provided values are now `#target`, `#build`, `#compiler`, `#config`, and `#source`. Target enum variants use unambiguous spellings such as `macOS`, `IOS`, `X86_64`, and `RiscvLp64`; Windows ISO code pages use names such as `Iso8859Part1`.
- **Canonical `macOS` spelling** — the operating-system package is `Rux/macOS`, source imports use `macOS`, and the built-in variant is `OperatingSystem::macOS` / `.macOS`. Manifest `TargetOS` and registry `target_os` values likewise use exact `macOS`; the former `MacOS` language and schema spellings are rejected without aliases before the 0.4.0 contract is released.
- **Native Linux calling convention** — ordinary and inline-assembly Rux functions now use the System V AMD64 ABI on Linux, including `rdi`/`rsi`/`rdx`/`rcx`/`r8`/`r9` integer arguments, 16-byte call-site stack alignment, and stack-passed overflow arguments. `#Abi(.Win64)` remains available as an explicit override.

- **Manifest Version 1** — `Rux.toml` is now a versioned, strictly parsed contract shared with the package registry, and the cutover is hard: every manifest opens with a `[Manifest]` table declaring `Version = 1`, and unversioned or legacy files are errors rather than being silently upgraded. `Type` is exactly `Executable`, `SharedLibrary`, `StaticLibrary`, or `SourceLibrary`; the retired `Program`, `Library`, and `Source` values are errors. `[Package]` gains `Namespace`, `Keywords`, `LicenseFile` and `ReadmeFile`, and `[Package].Version` must be a strict Semantic Version. `License` names the terms as an SPDX expression and `LicenseFile` carries their text inside the package; they are independent, so a package may declare either, both, or neither. `Repository` and `Homepage` must be absolute `http`/`https` URLs that carry a host and no credentials. Dependencies are inline tables — `Io = { Namespace = "Rux", Version = "^1.0.0" }` for a registry package and `Util = { Path = "../Util" }` for a local one — with an optional `Package` field when the import name differs from the package name; import names that collide after `_`-to-`-` lowercase normalization are rejected. Version requirements accept `*`, caret, tilde, comparator intersections and partial operands, and an operand with no operator is a caret requirement, so `1.2.3` means `^1.2.3` and `=1.2.3` pins. Parsing rejects malformed TOML, duplicate keys and sections, unknown sections and fields, wrong value types, and missing required fields, and every failure reports the manifest path, line and column instead of a bare "failed to parse". See the [manifest contract](Docs/Manifest.md).
- **The intrinsics package is `Rux/Core`** — the package supplying the compile-time context, the diagnostic directives, `Assert`/`Panic`, and the primitive and range types is named `Core` rather than `Rux`, so `rux add Rux/Core` reads as an identity instead of repeating itself, and the namespace introduced with Manifest Version 1 no longer stutters in every dependency table, cache path and registry route. Dependents bind it as `Core = { Namespace = "Rux", Version = "..." }` and write `import Core::{ #target, Assert }`; the name is a manifest's choice, so `Rux = { Namespace = "Rux", Package = "Core" }` keeps the old spelling for anyone who prefers it. Nothing had been published yet, so no released identity changes.
- **First-party packages publish under the `Rux` namespace** — every package under `Packages/` now declares `Namespace = "Rux"`, and they depend on each other through the registry form: `Memory = { Namespace = "Rux", Version = "*" }`. Repository test packages stay namespace-free on purpose, since they are built in place and never published, and continue to use `{ Path = "..." }` entries into `Packages/`. A repository-wide manifest-policy test enforces both halves along with the schema header, package type, dependency form, centralized test outputs and canonical formatting, so `rux fmt --manifest-only` is a no-op on every checked-in manifest.
- **Package kinds drive command behavior** — `Executable` links and runs a program; `SharedLibrary` emits `.dll` plus its Windows import `.lib`, `.so`, or `.dylib`; `StaticLibrary` emits `.lib` or `.a`; and `SourceLibrary` is compiled into dependents but cannot be built or run directly. `rux new` and `rux init` select the kind with mutually exclusive `--executable`, `--shared`, `--static`, and `--source` flags. Rux 0.4.0 permits `rux pack` and `rux publish` only for `SourceLibrary` packages.
- **Workspace test discovery** — `rux test` at a workspace root now discovers each member package's `Tests/` directory in addition to the root `Tests/`, so test packages can live beside the code they cover. Tests found under a member are labeled with the member's name (`Text/Tests/Compare` reports as `Text/Compare`), and a root `Tests/` keeps working as before.
- **Flat test executable output** — `rux test` writes each executable directly to its configured `[Build].Output` directory instead of adding a `Debug` or `Release` subdirectory. Ordinary `rux build` and `rux run` outputs remain profile-specific.
- **Artifact directories name the operating system and architecture separately** — an ordinary build writes to `<Output>/<Profile>/<OS>/<Arch>/` instead of `<Output>/<Profile>/<canonical-target>/`, so a Debug FreeBSD x86-64 build lands in `Bin/Debug/FreeBSD/x86-64/` rather than `Bin/Debug/freebsd-x86_64/`. The components use the display spellings — `FreeBSD`, `Linux`, `macOS`, `Windows` and `x86-64`, `AArch64` — while `--target`, `#target.triple` and CI artifact IDs keep the canonical machine spelling, and an alias such as `--target windows-arm64` still resolves to one directory. A non-host `rux test --target` build gains the same two components below its raw root. `rux build --all` names each cell's target by its display name — `Linux AArch64`, `Windows x86-64` — rather than as a canonical triple, and the target catalog now lists AArch64 before x86-64 within each operating system, so the matrix builds and reports in that order. Every build report prints its artifact path relative to the directory holding the manifest, falling back to the full path when the output root sits outside the package.
- **`rux install` resolves through the package registry** — the read half of the registry contract now ships, so installing a package no longer downloads source from GitHub. `rux install`, `rux update`, `rux add` and `rux info` read the registry's resolver index, and `--registry <url>` or `RUX_REGISTRY_URL` retargets them exactly as it retargets `rux publish`; the read routes are public, so no credential is involved. Resolution walks the whole dependency graph before anything is downloaded: a version is eligible when it is not yanked, its `MinRux` is no newer than the running compiler, and it satisfies every requirement gathered for that package, and the highest eligible version wins. One version is selected per package, and requirements that cannot hold together are reported rather than resolved arbitrarily. Each selection is downloaded as the published `.ruxpkg`, checked against the SHA-256 the registry publishes for it, and unpacked under the same archive contract `rux pack` applies, so an entry path cannot escape the package and a corrupted or substituted archive installs nothing. `[Dependencies]` version requirements are therefore honored for the first time — `Version = "^0.1.0"` used to be decorative.
- **Version-keyed package cache** — installed packages live at `<cache>/<namespace>/<name>/<version>`, using the spelling the package was published under for the namespace and name directories and the exact version text for the leaf, so several versions of one package can be installed at once and two projects no longer contend over one directory. An existing directory is matched by normalized name, so a manifest that spells a dependency `Namespace = "rux"` still resolves to the `Rux` the registry published rather than downloading a second copy beside it. `rux build`, `rux check`, `rux run` and `rux test` pick the highest installed version matching the manifest requirement, entirely from disk, so a build still needs no network; a requirement nothing installed satisfies now names the versions that are installed. `rux uninstall Namespace/Name` removes every installed version, and an added `@requirement` narrows it. `rux list --global` reports each version, and `rux list` names the version a build would actually use. A cache written by an earlier release is deleted on the next install and reinstalled under qualified identity.
- **Registry-shaped JSON and artifact reading** — the compiler gained a real JSON reader for the nested documents the registry answers with, a self-contained SHA-256, and a `.ruxpkg` extractor that verifies every entry's CRC-32 and holds a downloaded archive to the Artifact v1 limits. No third-party dependency was added.

#### Tooling

- **Hardened CI and releases** — all workflows use current action versions, least-privilege permissions, credential-free checkouts, bounded timeouts, consistent `x86_64` artifact names, and seven-day intermediate artifact retention. Every platform now runs C++ unit tests plus Rux check, lint, and test verification; release assets include SHA-256 checksums.
- **CMake 3.30 baseline** — Rux now accepts CMake 3.30 or newer while retaining policy behavior through CMake 4.3. FreeBSD CI uses the packaged CMake 3.31 release instead of spending more than 20 minutes building CMake from source.
- **Canonical architecture names** — documentation and CI labels use `x86-64` and `AArch64`; machine-readable target triples and artifacts use `x86_64` and `aarch64`; C++ and Rux architecture enums use `X86_64` and `AArch64`. The CLI still accepts `x64`, `amd64`, and `arm64` target suffixes as compatibility aliases and normalizes them before compilation.
- **Architecture-aware object and linker layer** — an RCU object records the machine it was compiled for as a named architecture rather than a fixed byte, and the relocation table gained the AArch64 kinds — `CALL26`, `JUMP26`, `CONDBR19`, `TSTBR14`, `ADR_PREL_PG_HI21`, `ADD_ABS_LO12_NC`, `LDST_ABS_LO12_NC`, `MOVW_UABS_G0` through `G3`, `PREL32`, and `PREL64` — whose split immediates a whole-field patch cannot express. The linker, the relocatable-object writer, and the archive writer take the target architecture alongside the target operating system, so the machine identifier stamped into an ELF, COFF, or Mach-O object follows the target instead of being fixed to x86-64. An object compiled for a different architecture than the link target, a relocation no object writer can encode yet, and an executable format that has no back end for the target architecture are each reported as an error rather than producing a silently corrupt artifact. `rux build --emit rcu` names the object's architecture and prints the new relocation names.
- **Hermetic consolidated tests** — repository tests are organized as language, package, unit/golden, and policy suites below `Tests/`. Every Rux test dependency is an explicit local path, while workspace-member overrides resolve transitive first-party dependencies without registry access.
- **A mistyped import separator is reported as one error** — `import Io:PrintLine;` reported that a `';'` was expected, then a second error that a declaration was expected, and offered a help listing every declaration keyword; none of it named the single missing colon. The parser now recognizes a lone `:` where the path separator belongs, reports `expected '::' in the import path` with `help: separate import path segments with '::', as in 'Io::PrintLine'`, and continues parsing the path so the rest of the declaration does not fail a second time. The `import Text:{Concat}` brace form recovers the same way.
- **Display spellings in report prose** — every progress and outcome line names the profile and target the way prose does: `Compiling App v0.1.0 (Debug, Windows x86-64)` and `Built App (Debug, Windows x86-64) in 22 ms`, across `build`, `run`, `test`, `check`, and `doc`, and in the `build --all` matrix columns. Canonical IDs such as `windows-x86_64` are now reserved for text naming a value that can be passed back on the command line, so `--target` diagnostics keep them. An alias still resolves visibly: `--target freebsd-arm64` reports `FreeBSD AArch64`.
- **Rebuilt `rux build --stats`** — the report is the ordinary build summary followed by four titled sections, `Time`, `Source`, `Optimization`, and `Performance`, each a heading over rows whose label column is sized to that section rather than to a hard-coded width. Facts are stated once: the status line carries the profile, target, and elapsed time, so the rows below it hold only the package version, compiler version, and artifact. A `Time` section that previously listed phases summing to a fraction of its own total now carries an `Other` row for the dependency resolution, manifest loading, and filesystem work no phase timer measures, plus a percentage column that reaches 100%. Phase names come from the same list `--verbose` uses, so `Analyzing`, `Lowering to HIR`, and `Emitting RCU objects` replace `Semantic`, `HIR`, and `Codegen`. The four files/lines/tokens/size blocks collapse into one `Local | Dependency | Total` grid, totals close the rows they sum instead of heading them, and the IR-node estimate leaves the pruning group it was never part of. `--stats` no longer suppresses the `Compiling` progress line.

#### Platform

- **AArch64 system-call wrappers** — `Syscall0` through `Syscall6` in the Linux, macOS, and FreeBSD packages now have real AArch64 bodies selected by `when #target.arch`, alongside the x86-64 ones they already had: the call number moves into `x8` (`x16` on Darwin), the arguments shift down one register into `x0`-`x5`, and `svc #0` (`svc #0x80` on Darwin) traps. macOS and FreeBSD normalize the carry-flag error convention to the `-errno` the Linux wrappers return. Darwin's syscall class, which only the x86-64 trap carries, is zero on AArch64 so the ordinals are passed bare. `Math`'s `Sqrt`, `FloatBits`, and `FromBits` likewise gained AArch64 bodies. The x86-64 build of every package is byte-for-byte unchanged.
- **Four operating systems, two architectures** — the supported matrix is now exactly FreeBSD, Linux, macOS and Windows on x86-64 and AArch64, and every one of those eight triples has a working back end. `rux build --target` accepts only those eight; a triple such as `openbsd-x86_64` or `linux-riscv64` is rejected up front by name rather than reaching a back-end gate. Because no accepted target can fail code generation, the separate "code generation for '<triple>' is not implemented yet" diagnostic is gone.

### Removed

- **The other BSDs, illumos, and every unbuildable operating system** — `#target.os` and the `OperatingSystem` enum named sixteen systems, of which most could never be produced; comparing against one warned that the branch would never run. Both are now the four a build can actually target, so the warning has no cases left and is gone with them. `TargetOS` in a manifest accepts the same four.
- **The 32-bit and RISC-V architectures** — `Architecture` drops `ARM32`, `RISCV32`, `RISCV64` and `X86Bit32`, leaving `AArch64` and `X86_64`. `DataModel` loses `ILP32`, `ApplicationBinaryInterface` loses `AAPCS`, `RiscvIlp32`, `RiscvLp64` and `WindowsX86`, `ObjectFormat` loses `Wasm`, and `TargetFeature` loses `RVV` — in each case because no supported target selects it. Both remaining architectures are 64-bit, so `#target.pointerBits` is always 64.
- **The `Bsd` package** — renamed to `Rux/FreeBSD`, and narrowed from the syscall interface shared by four BSDs to FreeBSD's own. Its per-OS syscall table collapses to the FreeBSD 14.4 numbers, and `Rux/Io` and `Rux/Memory` now depend on it under `TargetOS = ["FreeBSD"]`.
- **The Clang dependency for AArch64 output** — AArch64 artifacts used to be produced by transpiling LIR to a C translation unit and shelling out to the platform Clang driver for both lowering and linking. That path is gone: `CodeGen/AArch64/NativeEmitter` and the `FindNativeClang` search are deleted, `GenerateArtifact` has one shape for every target — LIR, then the `RcuEmitter` the target architecture selects, then `Linker` — and no file under `Compiler/` names or launches an external compiler any more. Nothing beyond the tools needed to build `rux` itself has to be installed to compile Rux programs, and an installed toolchain can no longer change what a build produces. The temporary `RUX_AARCH64_RCU` opt-in and its `CompileOptions::nativeAArch64Backend` counterpart, which selected between the two back ends while both existed, are gone with it.
- **Metadata blocks** — every `#{...}` declaration metadata block is now an error. Calling conventions use `#Abi(.C)`, `#Abi(.SysV)`, or `#Abi(.Win64)`; platform selection uses conditional compilation such as `when #target.os == .Windows { ... }`.
- **Compiler-parameter sigils** — the `$`-sigil compiler parameters, their flat aliases, and the `#Intrinsic("Name")` attribute are gone. Compile-time values are `#`-prefixed and declared with the `intrinsic` keyword.
- **Target-specific dependency sections** — `Rux.toml` no longer recognizes `[Dependencies.Target.<OS>]` (or the legacy `[Target.<OS>.Dependencies]`); only a single `[Dependencies]` table is allowed. Platform selection belongs in source with conditional compilation.
- **GitHub downloads and the `git` runtime dependency** — packages are no longer fetched from repositories. The flat name-to-repository index, the GitHub tree and `raw.githubusercontent` requests, and the `git clone` that backed them on Windows and was the only implementation on Unix are all gone, so `git` is no longer needed to use the toolchain — only to build it from source. Installing a package by bare name went with them: a registry package is identified by `Namespace/Name`, as `rux add` already required.
- **`rux install --dev`** — the flag existed only to clone a repository's `dev` branch, which has no meaning now that installs come from published, immutable versions. Use a version requirement, or a `{ Path = "..." }` dependency for unpublished work.

### Fixed

- **A field reached through a pointer to a generic instantiation** — the arguments an instantiation was made with are spelled in the name of the type that carries them, and a pointer has no name of its own, so reading them off the pointer found none. `Node<int32>` was then treated as the bare declaration and its fields were still spelled in the type parameters, which resolve to nothing outside the declaration -- a pair of errors that contradicted each other, one saying the parameter is not a type and the next saying the struct has no field, while listing that field among the ones it has. Nothing inside an `extend` block ever saw it, since there the parameters are in scope; it took a plain function holding a pointer to a concrete instantiation, which is what a linked structure hands out.
- **An instantiation passed as a type argument** — `Width<Node<T>>()` written inside a generic queued an instantiation of `Node<T>` itself, a type that does not exist, and never queued one for `Node<int32>` once the enclosing generic said what `T` was. The test for whether a type argument was still waiting on a parameter walked only the type's structure, and `Node<T>` keeps its argument in its name -- so it looked concrete, and the substitution that should have completed it walked past it for the same reason. A `sizeof` folded inside such an instantiation then had no layout to read and stopped the compiler where there was nothing left to ask. Both the test and the substitution now read the arguments spelled in a name, and a type argument named for the first time by an instantiation is laid out when that instantiation is validated. This is the shape every container that allocates nodes of its own has: a tree asking its allocator for a `TreeNode<K, V>` from inside `Tree<K, V>`.
- **Destroying an option whose payload is an aggregate** — the payload is reached by counting bytes from the start of the value, and a byte address has no fields to offset from, so a step reaching a field of the payload asked the back end for an offset it answered with zero. Every field of such a payload was therefore destroyed at the front of it: correct by accident when the field needing destruction sat first, and a destructor run over whatever preceded it otherwise — a pointer read out of an integer, and a fault. The payload pointer now says what it points at, so a field is found where it is. Reached by anything holding `Option<Entry>` where `Entry` keeps a key before its value, which is what an ordered container hands back.
- **A function name a program shares with one of its dependencies** — handing such a function over as a value gave a pointer that faulted when it was called, while a direct call resolved correctly, so the same name worked one way and not the other. Two things were wrong. Where a function lives was recorded as the `module` blocks around it and not the package it belongs to, and most files have no `module` block, so two packages declaring one name looked like one owner and nothing distinguished their symbols. And a reference to a function carried the name as written rather than the name it was emitted under, so the back end looked for a function it had not emitted, found none, and read the pointer out of a global that does not exist. A function's package is now part of where it lives, and a reference is lowered under the same name a call uses — the nearest declaration of it, which is the program's own, since a package is collected after everything it depends on. Nothing changes for a name only one package declares.
- **A generic enum composed only inside generic bodies** — `Option<V>` written in a container is named for the first time when the container is instantiated, and no line of the program spells `Option<Tracked>`, so the walks over what was written never reached that type. It had no layout, which stopped the compiler outright with an internal error, and no destructor, which was worse: what it held was never destroyed and nothing said so. Returning such a value out of a generic destroyed it twice instead, because the test for whether handing a value over consumes it read only a type's structure and a parameter spelled inside an instantiation's name is not structural. One name-aware test and one name-aware substitution are now shared by everything that defers a question until a type argument arrives. A single concrete mention anywhere in the program hid all of this, which is why it took a container whose element type is decided entirely by its callers.
- **Storing a value that occupies no bytes** — the back end sizes a move from its type, and a size of zero fell through to the eight-byte default meant for a width it could not work out. Those answer different questions: an unknown width has to guess, a known width of zero has nothing to do. A word was therefore written for a field occupying none, over whatever followed it — and a zero-sized field is nearly always followed by something, since that is why it is there. A set built as a tree of keys with no values put that field between a node's key and its links, so storing one replaced a link; the tree answered lookups correctly and fell over when something walked it. A move of nothing now moves nothing, on both the load and the store side.
- **A destructor built for a type that cannot exist** — a destruction plan is only useful for a type that can exist, and the test for that asked whether a type argument matched a parameter of the type being instantiated. That catches `Box<T>` written inside `extend Box<T>` and nothing else: a container built on another one hands down a parameter belonging to the outer type, so `Tree<T, Unit>` inside `TreeSet<T>` was judged concrete because `T` is not one of `Tree`'s parameters. Lowering then built a destructor for it, which asked the size of a node whose element type is still a parameter and stopped the compiler where there was nothing left to ask. A parameter and a declared type both arrive as a bare name, so what tells them apart is now whether anything declares the name.
- **A destructor's body analyzed at each type it is built for** — nothing in a program calls a destructor; the generated glue does. So a destructor body was never analyzed at the types it would be built for, and anything it deferred until its type arguments arrived went unanswered — a `sizeof` inside one folded to nothing, or reached lowering with no layout at all. Every droppable type's `Drop` is now queued as an instantiation alongside the calls the program writes. A destructor that only calls things the program also calls directly was analyzed through those calls, which is why this went unnoticed.
- **A conditional expression whose arm holds another one** — the value a conditional produces comes from the block its arm *ends* in, and the merge was told the block the arm *started* in. Those are the same block only when the arm builds no control flow of its own, so an arm holding another conditional gave the merge a value from a block that does not reach it, and none from the blocks that do. The verifier refuses that, so it was a build that failed rather than a program that ran wrongly — which is only true because the verifier is there.
- **A struct whose field types are declared later** — struct layouts were computed in one pass in declaration order, and a field whose struct had not been reached yet was sized as one word. Declaration order across a package is file order, so a struct in an alphabetically early file whose fields live in a later file was laid out wrong, and everything built from it read and wrote the wrong offsets. Layouts now repeat until none changes, which runs as deep as structs nest by value and no further. The hard-coded twenty-four-byte `StringBuilder` went with it: a type's declaration is its layout, and the fiction corrupted the frame of anything holding the real, larger one.
- **An interface stored in a struct field** — an interface value is a data pointer and a vtable pointer, but a field holding one was laid out as an ordinary named type and given eight bytes, so the vtable word landed on whatever field followed it. Reading it back loaded half the fat pointer and passed that as the value's address, and a call through such a field jumped into the data pointer. Struct layout now sizes an interface field as the sixteen bytes it is, and a field access hands back its address the way a local or an array element already did.
- **A droppable local with no initializer** — a `var value: Handle;` was marked as owning something from the moment it was declared, so the scope's cleanup ran the destructor over whatever the storage happened to hold. It starts owning nothing now, and becomes live when something assigns to it.
- **Destruction glue for an uninstantiated generic** — a plan was synthesized for `Box<T>` itself, not only for each `Box<int64>` that exists, and instantiating it lowered the generic body with the parameter substituted for itself — which left a `sizeof(T)` inside with no width and aborted the compiler. A plan whose type still names a type parameter describes nothing that can exist and is dropped.
- **A `when` match arm that consumed nothing** — an arm body written as a statement rather than an expression, such as `.Windows => return 1;`, parsed no expression and left the cursor where it was, so the arm loop ran forever building empty arms until the process exhausted memory. Each malformed arm is now reported once, naming the fix, and the loop cannot iterate without consuming a token.
- **A Win64 float argument passed on the stack** — the fifth and later floating-point arguments of a call were routed to their stack slots through `xmm0`, which by that point already held the call's first argument, so the callee received the fifth argument's value twice and never saw the first. A call with five or more float arguments therefore computed on the wrong operands, silently. The bits now travel through `rax`, which is an argument register under neither convention, so nothing already placed is disturbed.
- **A cast naming a type parameter** — `value as T` and `value as byte` for a generic `value` were both rejected outright, because whether a type can be cast was decided against the unsubstituted parameter, which is not yet any particular type. A generic could therefore convert nothing, which is what a checked conversion is made of. The check is now deferred to each instantiation and made against the substituted types, exactly as an operator applied to a `T` already was. An instantiation whose types genuinely do not convert is still reported, against the cast in the generic body, and a cast between two concrete types is unaffected.
- **Arithmetic between an integer above 64 bits and anything narrower** — an operator reads both operands at its own width, but a narrower one reached the back end still held at its own, so the operation read limbs the operand never wrote. `wide + 1` took in whatever followed the literal's eight bytes; so did `wide - offset` for a narrower `offset`, and `wide += 1`. Below 64 bits nothing showed, because the operand and the operation share a register either way. Both sides are now widened to the operation's type, the same rule comparison already applied. A shift's count keeps its own width, and pointer arithmetic still offsets by whole elements.
- **Integer limits above 64 bits** — `Min` and `Max` were computed by shifting a machine word by the type's width, which is undefined past 64 bits, so `uint128::Max` and every wider limit reported zero. They are now computed exactly, at any width, and `int512::Max + 1` wraps to `int512::Min` as it should.
- **A generic struct's field read inside a generic function** — reaching a field recovers the struct's type arguments by reading them back out of the receiver's printed name, where `T` the parameter and `T` a type that happens to be called that are one spelling. The parse answered "a type called `T`" every time, so a field declared `T` came out a different type from the `T` the enclosing function declared, and the two were reported against each other as `cannot assign 'T' to 'T'` — or, returning one, `'return' value must have type 'T', but found 'T'`. A type name read back out of a printed type is now matched against the type parameters in scope first, the same order a written `T` already resolved in, and slice element types go through that one reader instead of a second copy that knew only the primitives. A type genuinely named `T` is unaffected outside a generic, and shadowed inside one exactly as a written `T` already was.
- **A generic struct at a type argument wider than a pointer** — a generic struct was declared once and laid out once, from the unsubstituted type parameter, so every instantiation was charged a pointer's width for a field holding a `T` by value. `Box<int32>` and `Box<Two>` came out the same size: the wider one's initializer wrote past its own slot, faulting where the frame ended and silently corrupting a neighbouring value where it did not, with no diagnostic either way. Each instantiation now carries its own declaration with the arguments substituted into its fields, and both back ends size an instantiation from that rather than from the declaration it came from. Nothing that stores a `T` behind a pointer, such as `Array<T>` or `Slice<T>`, was affected, since its size never depended on `T`.
- **A type argument that is itself generic** — `Depth<Slice<int32>>(slice)` was rejected because the `>>` closing both argument lists was read as a right shift, while the same call written `Depth<Slice<int32> >(slice)` compiled. Only the parser can tell a run of closers from a shift, so the token is now split there: one `>` closes the inner list and the rest is left for the lists enclosing it. A `>>` that really is a shift still is one, including its compound and logical forms.
- **A generic function that instantiates itself without end** — a generic calling itself at a strictly larger type argument, such as `Grow<T>` calling `Grow<*T>`, never closes its set of instantiations, and deduplication cannot help because each one is genuinely new. The compiler followed the chain until it exhausted its stack and died with no diagnostic at all. A type argument is now bounded by its structural size, and an instantiation past the limit is reported against the function that caused it rather than followed. Recursion at a fixed type argument is unaffected, and the limit sits orders of magnitude above any type written by hand.
- **Integer literals on the left of an arithmetic operator** — two integer operands settled on the left one's type, and an unsuffixed literal carries the default `int`, so `2 * count` came out `int` where `count * 2` came out `uint`. The same expression mirrored: one spelling compiled and the other was rejected with `cannot assign 'int' to 'uint'`. A literal now takes the other operand's type whichever side it is written on. Two literals still settle on `int`, and an `int`-typed expression that is not a literal is unaffected, since it is assignable to no other width.
- **Integer literals at a call to an overloaded function** — an unsuffixed integer literal carries the default `int`, which is assignable to no other integer width. A call with a single candidate accepted one against any integer parameter, but the overload-resolution path did not, so giving a name a second overload stopped every existing call that passed a bare literal from resolving at all. Overload resolution now grants the same allowance, in its coercing pass only: an exact match still wins, so overloads distinguished by integer width still select by the argument's own type, and only `int` widens, so an explicitly typed argument is never silently narrowed.
- **Overloaded generic functions sharing one symbol** — two overloads of a generic function instantiated at the same type argument produced the same monomorphized name, so only the first was emitted and every call bound to it. A four-argument call reached the three-parameter overload and silently dropped an argument, returning the wrong answer rather than failing to build. Overloaded methods already carried their parameter types in the name; generic free functions now do too, so each overload gets its own symbol at each instantiation.
- **Comparison operators a struct does not declare** — only the exact operator a type declared was dispatched, and the rest fell through to comparing the operands' raw representation, quietly answering a question the type never defined. A struct whose `==` ignored a field reported `a == b` and `a != b` both true. An operator is now derived from the ones the type does declare, so declaring `==` and `<` gives a struct all six: `a != b` is `!(a == b)`, `a > b` is `b < a`, `a <= b` is `(a < b) || (a == b)`, and `a >= b` is `(b < a) || (a == b)`. A declared operator always wins over the derivation, and each operand is evaluated exactly once even where the derivation names it twice. `<=` is deliberately not `!(b < a)`, which would answer wrongly for a type with unordered values, where neither operand is less than the other nor equal to it. Where nothing can be derived the comparison is rejected, naming the operator to declare, rather than compared by representation. Enums, primitives and tuples are unaffected.
- **Writing through a read-only slice** — `values[0] = x` on a `Slice<T>` was accepted whenever the slice binding itself was declared `var`, and wrote through the read-only `*T` the slice borrows its elements with. That contradicted the same write spelled `*pointer = x`, which was already rejected. Mutability of the binding is the wrong question for a slice: declaring it `var` lets it be re-pointed, never rewritten. The write is now rejected with a help line pointing at `MutableSlice` from `Rux/Core`, the writable counterpart.
- **Aggregate copies and phi scratch wider than sixteen bytes** — two siblings of the array-sizing fix above, both from a width clamped rather than measured. A phi carrying an aggregate wider than sixteen bytes reserved eight bytes of scratch, the same kind of frame overrun; it is now sized from the value, as AArch64 already did. And `--emit asm` special-cased exactly sixteen bytes when copying an aggregate, so a twenty-four byte value printed a copy of only its first eight — executables were unaffected, since the object emitter always copied the full width. Both now copy and reserve whatever the type actually occupies.
- **`match` on an enum with a narrow base type** — an enum declared `: int8`, `: uint8`, or `: int16` matched no arm at all, yielding zero instead of any arm's value. A tag is stored at the enum's declared width but was read back as a full word, so the read picked up whatever sat beside it in the frame, and the mask meant to clear those bits was itself 32 bits wide — which is why `: int32` and wider happened to work. The tag is now read at the width it was stored, and the mask is applied only where something is actually packed beside it, so negative discriminants survive too. Comparing variants with `==` was unaffected at every width, so only `match` misbehaved.
- **Callback parameters in a generic function** — a parameter typed `func(T, T) -> bool` kept its type parameters unsubstituted, so no argument could ever be passed to it: handing a `func(int32, int32) -> bool` to a generic instantiated at `int32` was rejected as a mismatch between two spellings of the same type. A function type now substitutes like every other type in a generic signature, which is what lowering already assumed. Comparators, predicates, and transforms can be generic parameters — bearing in mind that a function value carries no captured state, since closures do not exist.
- **Arrays of structs wider than eight bytes** — a fixed array of any struct larger than eight bytes reserved too little stack and wrote past its own frame. The frame planner sized an array by delegating to a size function with no access to struct layouts, which charges eight bytes for a struct it cannot measure, so `Pair[3]` of a sixteen-byte struct reserved thirty-two bytes for forty-eight bytes of data and its last element overwrote the saved frame pointer and the return address. Initializing such an array faulted, in Debug and Release alike, without touching it afterwards. Sizing now recurses through arrays and tuples with the layout map in hand. The fault needed a function with more than one basic block, since a single-block function keeps its values in registers rather than stack slots — so a loop or a branch alongside the array was enough to trigger it.
- **Pointer arithmetic over a struct** — `ptr + n`, `ptr - n`, and `ptr += n` moved by whole elements only when the pointee was a primitive. A pointer to a struct advanced one *byte* per element, so `ptr + 1` on a `*Pair` landed four bytes short of `Pair`'s second element and reads and writes through it silently hit the wrong memory. The scaling multiply was emitted during lowering from `TypeRef::SizeInBytes`, a purely syntactic query with no layout table, which answers nothing for a named type — and the guard around it skipped the multiply rather than reporting the gap. Pointer arithmetic now offsets through the same `IndexPtr` instruction `ptr[n]` already used, scaled in the back end where the struct layout is known, so both spellings agree for every element type.
- **`when` conditions under a renamed intrinsics dependency** — a `when` condition only recognized a build intrinsic or built-in enum when the intrinsics package happened to be imported under the literal name `Rux`, because the fold matched the import spelling rather than the package it resolved to. `Package` exists so a manifest can bind a dependency to any import name, and doing so silently cost conditional compilation: identical source compiled under `Rux = { ... }` and failed with `unknown identifier '#target'` under `Core = { ... }`, while ordinary calls to the same intrinsics kept working. The driver now resolves which import names refer to the package by identity — reading the target manifest for a path entry, which is how repository tests reach it — and the fold matches those. Any alias works, including keeping `Rux`.
- **Constants of slice type** — `const Name: T[N] = [...]` and `const Name: char8[] = "..."` are now emitted into read-only data with a `{data, length}` header, instead of an eight-byte placeholder that was never filled in. Reading, indexing, iterating, or taking the `.length` of such a constant crashed at runtime. Elements may be literals, negated literals, or other named constants; anything the backend cannot lay out is now a compile error rather than a corrupt read.
- **Module scope in call resolution** — a call now binds to a function from its own module or from a module the file imports, in preference to a same-named function declared elsewhere in the program. Functions in different modules are no longer treated as overloads of one another, and two modules that would emit the same symbol are disambiguated by their module path, so importing one package could silently redirect a call into another.
- **Duplicate function signatures** — declaring the same function or method signature twice now reports the second declaration as an error. Functions with distinct parameter types remain valid overloads, and same-named functions in separate modules remain independent.
- **Dependency compilation** — `rux check` and `rux build` now share the same dependency-loading pipeline, so installed and path-based dependencies are available during semantic analysis and unresolved dependencies stop before code generation.
- **Call-site diagnostics on extern functions** — `#Error("...")` and `#Warn("...")` now emit their diagnostics when an extern function is called, including through module-qualified names, instead of being discarded after parsing.
- **Attributes on extend methods** — attribute calls such as `#Abi(...)` are accepted on methods inside an `extend` block instead of failing with "expected 'func' in extend body" (#197).
- **Zero-operand assembly parsing** — instructions such as `syscall` followed by `ret` are now parsed as two instructions instead of treating the second mnemonic as an operand.
- **AArch64 conditional branches inside a foreign-target `when` arm** — an `asm func` written under `when #target.arch { .AArch64 => ... }` failed to parse an x86-64 build with `expected an assembly mnemonic, found '.'` as soon as its body used `b.eq` or any other condition-carrying branch, because the dot joining a mnemonic to its condition was only read when the build already targeted AArch64. An untaken arm has to parse before it can be discarded, which is why `#` immediates were already read everywhere; the branch form now is too. A body that really is compiled for the wrong architecture still names the mnemonic that gives it away.
- **Methods of an `extend` on a concrete generic type** — `extend Slice<int> { ... }` and any other `extend` naming a generic type's arguments in full emitted each of its methods twice under one symbol: once with the block, and once more as a monomorphization requested by the first call site, whose receiver was a pointer where the block's was the value. Only a block already naming a type parameter of its own — `extend List<T>` — is monomorphized now.
- **`String` as a format argument** — `Format`, `Print`, and `PrintLine` rejected a `Text::String` argument with `cannot pass 'String' to variadic parameter of type 'Stringable'`. `Rux/Format` extended every primitive and `Slice<char8>` with `Stringable` but never `String` itself, so the one type the protocol hands back was the one type it would not accept, and `PrintLine("{}", text)` had to be written around. `String` now implements `Stringable` and renders as a copy of its own bytes — a copy rather than the receiver's block, because `Format` frees the String each argument renders itself into.
- **`DT_RELAENT` in dynamically linked ELF images** — the entry size was written only when the image also carried a `.rela.dyn`, so an ordinary dynamic executable declared `DT_JMPREL` and `DT_PLTREL = DT_RELA` with no entry size to read them by, and `readelf --use-dynamic --relocations` reported a corrupt dynamic tag instead of the PLT relocations. `DT_RELAENT` covers `.rela.plt` as well and is now always present.
- **Relocatable ELF object conformance** — a `StaticLibrary` package's `.o` members described a section at index 0, where an index of 0 means "none": the reserved null section header was written as `PROGBITS` with an alignment of 1 rather than all zeros, so `readelf -S` listed a phantom section. Their `.rela` sections also carried no flags, leaving `SHF_INFO_LINK` unset — the flag that says `sh_info` names the section the entries patch rather than being a count, as it is in a symbol table. Both are now written the way an assembler writes them.
- **ELF images cross-linked from another system** — the `PT_INTERP` loader path, the `EI_OSABI` byte, the C library an import with no library of its own binds to, the exit syscall of a static image and the process globals BSD libc expects were all chosen by the host the compiler ran on rather than by the target it linked for. A `linux-aarch64` image produced on macOS therefore named `/lib64/ld-linux-x86-64.so.2` — the x86-64 loader, in an AArch64 image — and a `linux-x86_64` image produced on FreeBSD asked for `libc.so.7` and exited through syscall 1. All of them now follow the target, so an image is the same bytes whichever host wrote it.
- **PE executables cross-linked from another system** — linking a Windows image whose imports name their DLL explicitly failed on a non-Windows host with `import DLL 'KERNEL32.DLL' was not found`, because the writer's early check of each import against its DLL's export table treated the host filesystem as authoritative for the target: the one place KERNEL32 is guaranteed to exist is the system being linked _for_, not the one linking. A PE import is resolved by name when the image is loaded, so the check is now advisory — a DLL the host can locate still has its export table read and each imported function verified, and one it cannot locate links exactly as declared.
- **Windows AArch64 image launch** — every image the PE writer produced was fixed-base and marked relocation-stripped, which x86-64 Windows loads happily but the ARM64 loader refuses with "%1 is not a valid Win32 application": Windows on ARM64 only loads relocatable, ASLR-capable images. The writer now records every 64-bit absolute fixup as an `IMAGE_REL_BASED_DIR64` entry in a `.reloc` section, clears `IMAGE_FILE_RELOCS_STRIPPED`, and opts into `DYNAMIC_BASE` with high-entropy addresses on both PE architectures, so an image stays correct wherever the loader places it.
- **macOS AArch64 image launch under current dyld** — the Mach-O writer moved rebased constant data into `__DATA_CONST` but left the segment's flags zero, and dyld refuses such an image with "__DATA_CONST segment missing SG_READ_ONLY flag" before `Main` ever runs. The segment now carries `SG_READ_ONLY`, so dyld applies its rebases and then re-protects the constant data read-only.
- **Relinked executables on macOS AArch64** — rewriting an existing executable truncated the old file in place, so the new image landed on the inode of the one it replaced. The Darwin kernel caches code-signature validity per vnode, and on arm64 — where the ad-hoc signature is load-bearing — executing a binary rewritten over a previously run one was sporadically killed before `Main`, which surfaced as a test binary failing with no output on its second run. The Mach-O writer now unlinks the output before writing so every image gets a fresh inode and a fresh verdict.
- **Windows AArch64 image version stamp** — relocatable ARM64 images still died during process initialization with `STATUS_INVALID_IMAGE_FORMAT` (0xC000007B) because the PE writer stamped operating-system and subsystem version 10.0, reasoning that ARM64 arrived with Windows 10. The ARM64 loader accepts exactly the 6.2 baseline the platform linker stamps — byte-patching a failing image's version fields to 6.2 makes it run, and 10.0 is the only field that kills it — so ARM64 images now carry 6.2, while x86-64 keeps its Vista baseline.
- **Windows MSI license packaging** — the installer now packages the canonical `LICENSE.md` file and displays the same copyright notice as the repository license.
- **Repository integration consistency** — FreeBSD package metadata now declares its `Rux` dependency, macOS scripts locate Homebrew's versioned LLVM 22 tools, CI enforces Rux formatting, and documentation consistently uses the `Build/` directory and centralized test workflow.
